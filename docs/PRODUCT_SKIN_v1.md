## 1-1. BAR — Product Shell

**Main 이 source of truth 다.** 상세페이지는 같은 상단 프레임을 유지한 채 필요한 것만 더한다.

```
Main    IDENTITY │ FLEX SPACE │                        COMMON TOOLS
                                                       [크게 보기] [DATE]

상세    IDENTITY │ FLEX SPACE │ DETAIL TOOLS         + COMMON TOOLS
                                [작성예시][미리보기]    [크게 보기] [DATE]
```

⛔ **COMMON 의 끝은 `[크게 보기][DATE]` 이고, 그 사이에 상세 도구를 넣지 않습니다.**
   그 둘이 **오른쪽 기준선**입니다. 서식마다 다른 단추가 끼면 화면을 옮길 때마다
   「크게 보기」와 날짜의 자리가 흔들려, 같은 제품으로 보이지 않습니다.
⚠️ 상세 도구는 **COMMON 앞**에 붙습니다 — 담당자 도구(`.btn.compact`) → 시민 도구 순.
⚠️ 「← 메인으로」는 BAR 가 아니라 **ASK navigation** 입니다(§3-3).

| 요소 | 규격(Main 실측 = 상세 동일) |
|---|---|
| BAR | 높이 **62px** · 좌우 padding **28px** · gap **18px** · `align-items:center` · 면 `#ffffff` · 아래 **1px `--m-border`** |
| 로고 | **38px**(공통 `GUNPO-LOGO` 블록이 정한다 — 화면 CSS 에서 덮어쓰지 마라) |
| 기관 표기 | **16.5px / 800 / 대표색** · `letter-spacing -.03em` |
| 구분선 | **1×15px `--m-border`** |
| 제품 이름 | 「민원 서식 작성 도우미」 **14px / 500 / `--m-ink-sub`** |
| 묶음 간격 | `.brand` gap **11px** · `.brand-tx` gap **11px** |
| **DATE** | **13.5px / 400 / `--m-ink-faint`** · `font-feature-settings:"tnum"` · `nowrap` · 형식 **`2026년 08월 28일 (금)`** · **최우측 고정** |

⛔ **좌·중·우 3등분을 쓰지 않는다.** 오른쪽 단추 수는 화면마다 다른데, 3등분이면 단추가
   하나만 늘어도 가운데 것이 움직인다. 가운데는 **빈 flexible space** 다 — 채우지 않는다.
⛔ **BAR 에 업무명(PAGE CONTEXT)을 두지 않는다.** 작성 영역이 이미 말하고 있어 중복이다.
⛔ **BAR 에 직접 인쇄 단추를 두지 않는다.** 인쇄는 **작성 → 미리보기 → 인쇄** 하나로 간다.
⛔ **파괴적 행동(초기화)을 BAR 에 두지 않는다.** 작성 내용에 대한 행동이므로 ASK 바닥이다
   (「처음부터 다시 작성」). Human Handoff 와 **시각 계층을 분리**한다 —
   Handoff = 지금 이 질문을 푸는 도움 · reset = 전부 버리는 행동.
⚠️ 상세의 실제 순서:
   `[작성예시(성인)] [작성예시(미성년)] [미리보기]` **│** `[크게 보기] [DATE]`.
   담당자 도구는 한 치수 작게(`.btn.compact`) 두고, ⛔ 시민 화면에 「테스트용」 같은 말을 쓰지 않는다.
📌 **작성의 Primary CTA 는 BAR 가 아니라 ASK 의 [다음]·[신청서 인쇄]다.**
   지금 BAR 의 [미리보기]만 강조돼 보이는 것은 **색 체계의 문제**이고, 아래 후속 항목에서 함께 본다.

## 1-2. Typography — Normal 은 Main 의 밀도, Big 은 따로

📌 **Normal 과 Big 은 다른 목적을 가진 두 눈금입니다.**
Normal = 서서 보는 보통 거리 · Big = 「크게 보기」를 누른 사람. 크게 보기가 있는 제품에서
**Normal 이 큰 글씨 몫까지 지면 안 됩니다** — 목록(Main)에서 작성(상세)으로 넘어올 때
글자가 갑자기 커집니다. 2026.07 「어르신 가독성 강화」 눈금이 그 상태였고 여기서 걷었습니다.

| 역할 | Normal | Big | 대응하는 Main 역할 |
|---|---|---|---|
| Question(질문) | **28** | 40 | CENTER 제목 30 |
| Description(설명·「왜 묻는지」) | **15** | 20 | 리드 16 |
| Field label | **16** | 21 | 리드 16 |
| Input / 입력칸 높이 | **18 / 56px** | 24 / 72px | — |
| Card title / description | **18 / 14** | 23 / 17.5 | 민원명 19 / 14 |
| 본문 기본 | **15.5** | 19 | item 15 |
| 요약 줄 | **15** | 18.5 | item 15 |
| 보조 설명 | **13** | 15 | note 13.5 |
| CTA | **17 / 56px** | 21 / 72px | CTA 18 |
| BAR 단추 / compact | **14 / 13** | 같음(⛔ 커지지 않음) | BAR 단추 14 |
| RAIL 머리 / 항목 / 보조 | **15 / 13.5 / 12.5** | 16.5 / 15 / 13.3 | 15 / 13.5 / 12.5 |
| metadata(날짜) | **13.5** | 같음 | 13.5 |

⛔ **손끝 표적은 `--touch-min` 48px 아래로 내리지 않습니다.** 입력칸 56 · CTA 56 · 카드 116.
⛔ **Big 을 더 키우지 않습니다.** Big 은 정보밀도보다 가독성이 먼저이고, **세로 스크롤이
   늘어나는 것은 받아들인 결과**입니다(2026.08.28 결정). 그것을 줄이려고 글자를 다시 깎거나
   컴포넌트를 압축하지 마십시오. 조건은 **가로 넘침 0 · 잘림 없음 · PAPER/RAIL 침범 없음** 뿐입니다.

### 어디에 두는가 — ⛔ 공통 블록에 넣지 마라

여권의 축소값은 **그 파일의 지역 `:root`**(`MAIN-SKIN` 블록 **뒤**)에 있습니다.

- ⛔ `<!--DESIGN-TOKENS v1-->` 안에서 고치면 **9개 화면 공통성이 깨집니다**
  (`check-design-tokens.py` 가 잡습니다). 실제로 이번에 한 번 그렇게 넣었다가 되돌렸습니다.
- ⚠️ 지역 `:root` 는 공통 블록보다 **뒤에** 오므로 일반 보기에서 이깁니다.
- ⚠️ `html.big`(공통 블록 안)은 선택자 우선순위가 높아 **크게 보기 값은 그대로**입니다.
- 📌 7종에 옮길 때는 이 `:root` 묶음을 **통째로** 가져갑니다.

### 한국어 조판 — 어절을 쪼개지 않는다

```css
.task-col,.rail-col{word-break:keep-all;overflow-wrap:anywhere;}
```

- ⛔ **어절 중간에서 줄을 바꾸지 않습니다.** 「신청하시나 / 요?」는 읽는 사람을 한 번 멈춥니다.
- ⚠️ 아주 긴 **한 낱말**(로마자 이름·주소)이 칸을 넘칠 수 있어 `overflow-wrap:anywhere` 를
  안전망으로 함께 둡니다 — **그때만** 쪼갭니다.
- ⛔ **화면마다 `<br>` 을 박아 개행을 맞추지 마십시오.** 문구·글자 크기·기관명이 바뀌면
  그 자리가 어긋나고, `rebrand.py` 로 이름이 긴 기관에 가면 바로 깨집니다.
- ⛔ **선택자를 나열하지 마십시오.** 읽는 두 기둥에 규칙 하나를 겁니다 — 나열식으로 해 보니
  `.sug-note` 하나가 빠져 거기서만 쪼개졌습니다.
- ⛔ 인쇄층(`.form-col`·`.ov`·`.paper`)에는 걸지 않습니다. 거기는 좌표로 찍는 자리입니다.

Blue = 안내. 값은 공통 토큰(`--warn-*`·`--notice-*`)을 씁니다.

### 3-1. Button Role 4종 — **이 넷이 전부다**

| Role | 어디에 | 높이 | 글자 | padding | 반경 | 아이콘 |
|---|---|---|---|---|---|---|
| ① **CTA** | ASK 바닥 [이전]·[다음]·[신청서 인쇄] | **56**(Big 72) | **17**/800(Big 21) | `0 16` | **6** | 16 |
| ② **Body Button** | 본문 안의 행동(Handoff 단추·예시 적용·모르겠어요) · **「← 메인으로」** | 36~44 | 13.5~15/700~800 | `8 12`~`11 15` | **6** | 16~18 |
| ③ **BAR Utility** | 상단 바 도구 | **38**(compact **33**) | **14**(compact **13**)/700 | `9 12` / `7 10` | **6** | 16 |
| ④ **Compact / Tertiary** | 「처음부터 다시 작성」 | **33** | **13.5**/700 | `8 13` | **6** | 15 |

⛔ **같은 role 안에서 높이·글자·반경을 새로 만들지 마십시오.** 새 화면이 생겨도 이 넷 중
   하나를 고릅니다. 어느 것에도 맞지 않는다면 그것은 새 버튼이 아니라 **잘못 설계된 행동**입니다.
⛔ **반경은 전부 6 입니다.** 판·카드(8~12)와 다릅니다 — 누르는 것과 담는 것을 그렇게 가릅니다.
⛔ **크기로 위계를 만들지 마십시오.** [이전]과 [다음]은 폭·높이·반경·글자·아이콘·정렬이
   **완전히 같고**(1920 실측 201×56), 다른 것은 **색과 면**뿐입니다. 종전에는 `150px 1fr` 이라
   [다음]이 세 배 넓었는데, 그렇게 하면 「짝」으로 읽히지 않습니다.
⚠️ BAR 단추는 **크게 보기에서 커지지 않습니다**(결정 ⑳). 두 보기에서 같은 값입니다.

### 3-2. ASK Navigation Zone

```
[← 이전]          [다음 →]        ← 같은 크기 한 쌍(1fr 1fr · gap 12)
        [↺ 처음부터 다시 작성]     ← 그 아래 가운데, Role ④
```

⛔ 좌표를 손으로 맞추지 마십시오. 이 규칙 하나가 자리를 정합니다.

### 3-3. 「← 메인으로」와 「처음부터 다시 작성」 — 뜻이 다르니 계층도 다릅니다

| | 자리 | Role | 조형 | 뜻 | 확인 절차 |
|---|---|---|---|---|---|
| **← 메인으로** | ASK **맨 위**(`.ask-nav`) | **② Body Button** | 대표색 1.5px 테두리 · 대표색 글자 · 흰 면 · 15px | **업무 이탈** — 이 서식을 떠나 허브로 | 없음(무동작 3분·인쇄 후 초기화가 값을 지웁니다) |
| **↺ 처음부터 다시 작성** | ASK **맨 아래**(`.ask-reset`) | **④ Compact-Tertiary** | 회색 1px 테두리 · 잉크 글자 · 13.5px | **현재 업무 초기화** — 지금 적은 것을 전부 버림 | **있음**(`askConfirm` → `resetAll`) |

⚠️ **hover 없이도 누를 수 있는 것임이 보여야 합니다.** 둘 다 테두리와 면이 그 몫입니다 —
   종전에는 글자만 떠 있어 **터치 화면에서는 알 길이 아예 없었습니다.**
⚠️ 2026.08.29 — 「메인으로」가 **너무 조용해서 눈에 안 걸린다**는 현장 의견에 따라
   Role ④ → **Role ②** 로 올렸습니다. BAR 의 [미리보기]와 같은 family 의 **테두리 변형**입니다.
⛔ **채운 대표색(solid)으로 만들지 마십시오.** 이 화면에서 앞으로 가는 길은 [다음]이고,
   위아래에 채운 파란 단추가 둘이면 어느 쪽이 진행인지 흐려집니다.
⛔ **초기화는 올리지 마십시오.** 되돌릴 수 없는 행동이라 가장 조용해야 합니다.
⛔ 초기화를 BAR 에 두지 마십시오(§1-1). 작성 내용에 대한 행동입니다.
⛔ Human Handoff 와 시각 계층을 겹치지 마십시오 — 저기는 **지금 이 질문**을 푸는 도움입니다.

| 버튼 안 | 16×16 |
| 글줄 안 | 18~19×18~19 |
| RAIL 아이콘판 | 판 30×30 · 아이콘 19×19 |

⛔ **이모지를 화면에 그리지 않습니다**(OS·글꼴마다 모양이 달라지고 색이 여럿입니다).
⛔ 아이콘 폰트·외부 세트를 받아 오지 않습니다(오프라인) — 인라인 SVG 로 둡니다.
📌 화면 데이터(`SCREENS` 등)의 이모지 문자열은 **고치지 않고**, 그리는 자리에서
`svgIcon()` + `EMOJI_ICON` 매핑으로 바꿔 끼웁니다. 매핑에 없으면 이모지로 물러납니다.
⚠️ 감정이 실리는 민원(사망·이혼)의 상징은 세게 쓰지 않습니다. 작은 크기에서 뜻이 서지
않으면 **문맥을 지키는 다른 그림**으로 바꿉니다(예: 맞잡은 손 → 사람 + 위임장).

## 5. RAIL

정보 위계 **작성 진행 → 준비물 → 안심 → 이용 안내**. 이 순서를 바꾸지 않습니다.

- 준비물은 **compact 표현** — 30px 아이콘판 + 이름 한 줄 + 조건 한 줄 · **≈35px/항목**
- ⛔ Main CENTER 의 큰 미니 그래픽(120px)을 축소해 옮기지 않습니다
- ⛔ 준비물 **조건을 지우지 않습니다.** 두 줄이 되면 칸을 키우지 말고 **문구를 줄입니다**
- **합격 조건: 상시 스크롤 없음.** 그 서식의 **가장 정보가 많은 조합**으로 재고,
  일반·크게 모두 넘침 0 이어야 합니다(여권의 최악 조건 = 미성년 + 기존 여권 = 준비물 6개)
- ⛔ RAIL 에 「지금 해야 할 행동」을 두지 않습니다 — 행동은 ASK 가 맡습니다

## 6. Human Handoff — 하나의 Family, 두 Variant

- 자리는 **ASK 바닥 고정**(`#askFoot`) · 위에 1px 실선으로 질문과 분리
- 그 화면에 탈출구가 없으면 **0px**(`:empty`) — 자리를 먹지 않습니다
- 질문 본문이 길어 굴러도 **항상 접근 가능**해야 합니다
- ⛔ 무엇을 낼지·눌렀을 때 무엇을 할지는 각 서식의 데이터가 정합니다(자리만 이 문법)
- ⛔ 의미·조건·`toCounter` 는 조형 작업에서 건드리지 않습니다

### 두 변형

| | **Panel Variant** (`.ask-box`) | **Inline Variant** (`.card-sub`) |
|---|---|---|
| 언제 | 제목 + 설명 + 행동이 **모두** 필요한 안내형 (예: 로마자 — 한 번 정하면 바꾸기 어렵다) | **한 줄 자체가 행동**인 compact 형 (예: 「어디에 해당하는지 모르겠어요」) |
| 짜임 | 2단 격자 — 위 `[아이콘][제목·설명]` · 아래 **폭을 다 쓰는 단추**(Role ②) | 아이콘 + 라벨 한 줄, 가운데 정렬 |
| 글자 | 제목 15.5/800 · 설명 13.5 · 단추 14.5/800 | 라벨 15/700 |
| 테두리 | 1px **solid** | 1px **dashed** |

**공유하는 것**(⛔ 변형끼리 달리하지 마십시오) — **반경 12** · **아이콘 문법 18px** ·
눌림 반응(테두리·글자 색 120ms 전환) · ASK 바닥이라는 자리 · `:empty` 규칙.

**허용하는 차이** — 내용 구조(제목·설명의 유무)와 그에 따른 **typography weight** 정도.

⛔ **Panel 을 가로 한 줄로 되돌리지 마십시오.** 질문 기둥이 495px 인데 아이콘·글·단추를
   한 줄에 놓으면 글에 220px 밖에 남지 않아 제목이 세 줄로 접힙니다(어절을 지키면 더).
   기관명·문구가 길어지는 다른 기관에서는 더 심해집니다.
📌 톤(Panel = 따뜻한 노랑 / Inline = 중립)은 **아직 다릅니다.** 색은 아래 후속 항목입니다.
