## 1. 이게 무엇인가

**민원실 창구 앞에 놓인 키오스크**에서, 시민이 관공서 신청서를 **작성해 인쇄해 가는** 프로그램입니다.
접수·전송은 하지 않습니다. 종이를 뽑아 창구에 내는 것으로 끝납니다.

서식 8종 — 여권발급신청서 · 혼인 · 출생 · 사망 · 개명 · 이혼(친권자 지정) 신고서 ·
증명서 발급신청 · 부동산거래계약 신고서.

화면은 **왼쪽에 묻는 곳(질문면)**, **오른쪽에 실제 서식** 으로 되어 있습니다(2026.08.25 통일).
시민이 질문면에 답하면 서식 위 제자리에 값이 얹혀 보이고, 그 상태 그대로 인쇄됩니다.
여권만 그 사이에 **안내 기둥(RAIL)** 이 하나 더 있어 세 단입니다.

## 2. 누가 어떤 상황에서 쓰는가

- **민원실에 온 시민.** 어르신 비중이 높습니다. 처음 쓰는 사람이 대부분이고 다시 오지 않습니다.
- **서서, 뒤에 사람이 기다리는 채로** 3~10분 안에 끝내야 합니다.
- 화면은 **터치**로 고르고, 이름·주소처럼 글자를 치는 칸은 **물리 키보드**로 칩니다
  (화면 키보드는 쓰지 않기로 했습니다 — 한글 조합이 어렵고 어르신에게 더 헷갈립니다).
- **뒷사람에게 앞사람 내용이 보이면 안 됩니다.** 3분 무동작·인쇄 후 자동으로 화면을 지웁니다.
- 목표는 "예쁜 화면"이 아니라 **창구에서 반려되지 않는 종이 한 장**입니다.

## 3. ⛔ 건드리면 안 되는 것 (가장 중요)

**인쇄물은 손대지 마십시오.** 인쇄되는 종이는 정부 별지서식 이미지 위에 값을 **절대좌표**로
얹어 만듭니다. 좌표가 1pt만 밀려도 접수처 스캐너가 못 읽습니다. 자동 검사(`verify-print.py`)가
인쇄 결과를 픽셀로 비교해 지키고 있습니다.

| | 바꿔도 되는가 |
|---|---|
| 안내 패널, 상단 바, 카드, 버튼, 색, 글자 크기, 여백, 배치 | **네** |
| 서식 이미지 위에 값이 얹히는 위치·크기·글꼴 | **아니요** |
| `@media print { … }` 안의 규칙 | **아니요** |
| 서식 이미지 자체 | **아니요** (법정 서식입니다) |

`현재-스타일.css` 에서 `@media print` 블록은 표시해 두었습니다. 그 밖은 자유롭게 보셔도 됩니다.

## 4. 지금의 디자인 체계

색은 **대표색 하나에서 계산**합니다. 기관마다 대표색이 다르므로(이 프로그램은 다른 지자체에도
배포됩니다) **특정 색을 전제로 한 디자인은 쓸 수 없습니다.**

```css
--blue        기관 대표색            (명도 30~55% 로 제한 — 흰 글씨 대비 확보)
--blue-dark   그보다 어두운 색        (대표색에서 계산)
--blue-light  아주 옅은 배경색        (대표색에서 계산)
--grad        135° 그라데이션         (대표색에서 계산)
--ink #1a1c1f  --muted #5b626c  --line #d5d9df  --bg #f2f4f7
```

- 글꼴 : `"Malgun Gothic"`(맑은 고딕) — 관공서 PC 에 반드시 있는 글꼴입니다.
  **다른 글꼴을 제안하시려면 설치 없이 쓸 수 있는지** 같이 알려 주십시오.
- 기본 글자 크기 17px, 카드 라벨 18~21px, 여권 카드 버튼은 높이 90px 안팎.
- 아이콘은 전부 **이모지**입니다(아이콘 폰트·SVG 세트를 넣지 않았습니다).

## 5. 우리가 이미 알고 있는 문제

이것들은 이미 압니다. **여기에 더해 무엇이 문제인지** 봐 주시면 좋겠습니다.

1. **여권만 흐름이 다릅니다.** 2026.08 에 여권을 큰 터치 카드 흐름으로 갈아엎었는데
   (`pass-01`), 나머지 7종은 아직 **입력 폼 + 단계 표시** 방식입니다(`form-01`~`08`).
   ⚠️ **아직 남은 문제입니다.** 2026.08.25 에 자리(상단 바·좌우·단계 표시)는 맞췄지만
   **흐름은 그대로**입니다 — 3영역 전환은 별도 과제로 두었습니다.
2. ~~좌우 배치가 서식마다 다릅니다~~ → ✅ **2026.08.25 에 맞췄습니다.**
   8종 모두 **질문면 왼쪽 / 서식 오른쪽**입니다.
3. ~~1920×1080 에서 여백이 많이 남습니다~~ → ✅ **2026.08.25 에 맞췄습니다.**
   7종의 `max-width:1420px` 를 걷어내 화면을 다 씁니다(허브·여권은 이미 그랬습니다).
4. ~~단계 표시가 두 가지입니다~~ → ✅ **2026.08.25 에 맞췄습니다.**
   8종 모두 「진행 n / N」 + 막대입니다. 지나온 단계로 되돌아가는 길은 남겼습니다.
5. **hover 로만 보이는 안내가 남아 있습니다.** 터치에서는 뜨지 않습니다.
6. 이모지 아이콘이 OS·글꼴에 따라 다르게 보입니다.
7. **세로 화면에서 서식이 오른쪽으로 잘립니다**(`pass-01-경로선택-세로`). 두 단 배치를 그대로
   세워 놓아서 그렇습니다. 아래쪽은 반대로 크게 비어 있습니다. 세로형을 쓸 기관이 있다면
   **위아래 배치**로 바꾸는 등 별도 안이 필요해 보입니다.
   ⚠️ 2026.08.25 에 7종에서는 **패널이 서식 위에 겹쳐 글자가 가려지던 것**만 고쳤습니다
   (서식 폭을 자리에 맞춤). 「세로형 별도 배치」는 여전히 남은 문제입니다.

## 6. 봐 주셨으면 하는 것 (질문)

1. **8종을 하나의 조작법으로 묶는다면 어느 쪽으로 가야 합니까?**
   여권의 큰 카드 흐름으로 통일 / 지금의 폼 흐름을 다듬어 통일 / 제3의 안.
   어르신·서서 쓰는 상황·3~10분이라는 조건에서 판단해 주십시오.
2. **큰 화면(1920×1080)을 어떻게 쓰는 것이 좋습니까?** 서식을 더 크게 볼지, 안내를 키울지,
   양쪽 폭 비율을 어떻게 둘지. 세로형 화면(1080×1920) 갈무리도 넣어 두었습니다 —
   **가로·세로 중 어느 쪽이 이 용도에 맞는지**도 의견을 주시면 좋겠습니다.
3. **지금 입력한 값이 서식 어디에 들어갔는지** 시민이 알아보게 하려면? 지금은 값이 조용히
   얹힐 뿐이라, 자기가 뭘 채웠는지 서식에서 찾기 어렵습니다.
4. **「비어 있는 칸」의 표현.** 이 프로그램은 빈칸을 6가지로 구분합니다 — 입력완료 · 인쇄 후
   직접 작성 · 기존자료 활용 · 해당 없음 · 창구 확인 · 미입력. 지금은 요약 화면에서 글자
   꼬리표로만 구분합니다(`pass-04`). 서식 위에서도 구별되게 하는 게 좋을까요?
5. **창구로 넘기는 화면**(`pass-05`)은 오류 화면이 아니라 **정상 완료의 한 종류**입니다.
   지금 디자인이 그렇게 읽힙니까? 실패처럼 보이지 않게 하려면?
6. **대표색이 기관마다 바뀌어도 무너지지 않는** 색 쓰임새를 제안해 주십시오
   (지금은 대표색·어두운색·옅은색·그라데이션 네 개만 씁니다).
7. **접근성** — 어르신 기준 글자 크기·대비·터치 목표 크기가 지금 충분합니까?
8. 이모지 아이콘을 계속 써도 될지, 대안이 있다면 **설치 없이** 되는 방법으로.

## 7. 답을 주시는 방법

- **글(마크다운)로 주셔도 됩니다.** 무엇을 왜 바꾸는지가 제일 중요합니다.
- 구체적인 값이 있으면 좋습니다 — `현재-스타일.css` 위에서 고쳐 주시거나,
  「이 규칙을 이렇게」 식으로 적어 주셔도 저희가 원본에 옮깁니다.
- 시안 이미지를 주시면 그대로 참고합니다. **다만 인쇄되는 서식 영역은 바꾸지 마십시오.**
- 우선순위를 매겨 주시면 좋겠습니다. 시범운영 중이라 한 번에 다 바꾸기는 어렵습니다.
