# 여기서부터가 AI에게 주는 내용입니다

## 1. 무엇을 만들고 있는가

군포시 민원실 **창구 옆에 놓인 키오스크**입니다. 시민이 질문에 답하면 정부 공식
신청서(여권·출생·혼인·사망·개명·이혼·가족관계증명서·부동산 8종)가 화면 오른쪽 실물
서식 위에 채워지고, 다 되면 **종이로 인쇄해 창구에 냅니다.** 접수도 전송도 하지 않습니다.

| | |
|---|---|
| **화면** | 1920×1080 가로, 일부 기관은 1080×1920 세로 |
| **거리** | **서서** 봅니다. 앉아서 보는 웹사이트가 아닙니다 |
| **쓰는 사람** | 민원실 방문 시민. **고령자가 많습니다** |
| **입력** | 터치 · 마우스 · 물리 키보드를 **모두** 씁니다 |
| **환경** | **오프라인 Electron(Chromium 130)**. 인터넷이 없습니다 |
| **글꼴** | `Malgun Gothic` 하나. ⛔ **웹폰트를 받을 수 없습니다** |
| **배포** | 배포본 하나를 **여러 기관이** 씁니다. 기관마다 대표색이 다릅니다 |

화면은 언제나 **세 영역**입니다 — 왼쪽 ASK(묻는 곳) / 가운데 PAPER(종이) / 오른쪽 RAIL(안내).
그 위에 BAR(상단 바)가 있습니다. **이 네 구역은 어떤 상태에서도 생기거나 사라지지 않습니다.**

## 2. 절대 조건 — 여기를 넘으면 답을 쓸 수 없습니다

| | |
|---|---|
| ⛔ **인쇄물** | 정부 별지서식 이미지 위에 **절대좌표**로 값을 얹습니다. **1pt 밀리면 접수처 스캐너가 못 읽습니다.** `@media print`·서식 이미지·`--marker-sign` 은 **대상이 아닙니다** |
| ⛔ **레이아웃** | 구역 폭·비율·정보 위계·「무엇이 움직이고 무엇이 남는가」는 **동결됐습니다**. 값만 정해 주십시오 |
| 🎨 **대표색** | `--blue` 계열 4개는 **기관 설정에서 계산해 주입**합니다(군포는 파랑, 안양은 초록…). ⛔ **특정 색을 전제한 안은 쓸 수 없습니다** |
| 🔤 **글꼴** | `Malgun Gothic` 고정. 크기·굵기·자간만 만질 수 있습니다 |
| ♿ **감소 모션** | `prefers-reduced-motion` 에서 동작해야 합니다 |
| 🖥 **성능** | 재사용 사무용 PC에서도 돌아야 합니다. ⛔ 무거운 blur·큰 면적 그림자·동시 다중 애니메이션 금지 |

## 3. 과제 A — 모션

지금 **모션 토큰이 아예 없습니다.** 값이 5개 원본에 8곳 흩어져 하드코딩돼 있고
종류가 이미 5가지입니다(`.12s` `.15s` `.2s` `.22s` `.34s`), easing 은 대부분 **방치**돼 있습니다.

**A-1. 아래 토큰의 값을 정해 주십시오.** (이름은 예시입니다. 개수·이름을 바꾸셔도 되지만
**여섯 개를 넘기지 마십시오** — 늘어나면 다시 흩어집니다.)

```
--dur-quick   ?     즉답(눌린 표시·hover)
--dur-base    ?     펼침·접힘·나타남
--dur-calm    ?     종이 갈아끼우기처럼 느긋한 것
--ease-out    ?     들어오는 것
--ease-in     ?     나가는 것
--ease-move   ?     자리를 옮기는 것
```

**A-2. 아래 동작 각각에 어느 토큰을 쓸지 배정해 주십시오.**

| # | 동작 | 지금 값 |
|---|---|---|
| 1 | 카드에 마우스를 얹거나 키보드 포커스가 갔을 때 | `.12s` |
| 2 | 카드를 눌러 **설명판이 펼쳐짐 / 접힘** | `.22s` |
| 3 | 가운데 **종이가 다른 서식으로 갈아끼워짐** | `.34s` 흐림 |
| 4 | 시연이 **다음 카드로 넘어감**(아래 A-3) | 2.6초마다 |
| 5 | 여권 상단 **진행 막대**가 늘어남 | `.2s` |
| 6 | 여권/8종 **선택 카드**를 누른 순간 | `.15s` |
| 7 | **입력 오류 표시**가 나타남 | 없음(즉시) |
| 8 | **인쇄 전 안내 모달**이 나타남 / 사라짐 | 없음(즉시) |
| 9 | 인쇄 후 **개인정보 덮개**가 화면을 덮음 | 없음(즉시) |
| 10 | **크게 보기**를 켜고 끔(세 영역 비율이 2:3:1 → 5:5:2) | 없음(즉시) |
| 11 | Writing 에서 **질문 → 다음 질문** | 없음(즉시) |
| 12 | 종이 위 **Current Focus 가 다음 칸으로** 이동 | 없음(즉시) |
| 13 | 시연 중 종이 위 **줄이 한 줄씩 그어짐**(아래 A-3) | 한 줄 `.34s` · 줄 사이 약 0.26초 |

> ⚠️ **「없음」을 전부 채우라는 뜻이 아닙니다.** 넣지 않는 편이 나은 것은 **「넣지 않음」이라고
> 적고 그 이유를 써 주십시오.** 안 움직이는 것도 결정입니다.

**A-3. 대기 시연의 리듬**

아무도 안 건드리면 화면이 스스로 **왼쪽 카드를 하나씩 짚으며 가운데 종이를 그 서식의
것으로 바꾸고, 그 종이 위에 줄을 한 줄씩 그어 갑니다.** 마우스가 움직이기만 해도 멈춥니다.
지금은 **한 카드에 1.8초**(8종이면 한 바퀴 14.4초)이고, 그 안에서 **줄 5개**가 차례로 그어집니다.

> ⚠️ 시연의 종이는 **실루엣**입니다 — 서식 이름과 항목 줄만 있는 종이 모양입니다.
> **실제 서식은 시민이 카드를 고른 뒤에만** 나옵니다(§6 참조). 시연·hover 까지 실제
> 서식을 띄우면 눌러도 화면이 그대로인 것처럼 보이고, 빽빽한 정부 서식이 몇 초마다
> 바뀌어 부담스럽습니다.

- 이 시간이 적당합니까? 아니면 몇 초입니까?
- 카드가 넘어갈 때와 종이가 바뀔 때, **어느 쪽이 먼저**여야 합니까?
- 한 카드에 머무는 동안 줄 5개를 다 긋는 것이 맞습니까, 몇 줄만 긋다 넘어가야 합니까?
- 한 바퀴를 돈 뒤 **쉬어야 합니까**, 계속 돌아야 합니까?

**A-4. `prefers-reduced-motion` 일 때** — 지금은 **시연을 아예 돌리지 않습니다.**
이 판단이 맞습니까? 그 밖에 무엇을 꺼야 합니까?

## 4. 과제 B — 시각

**갈무리(§7)를 보고** 아래 값들을 다시 정해 주십시오.
⛔ **전부 바꾸지 마십시오.** 지금 값을 그대로 두는 것도 답입니다 — **고칠 것만** 적어 주십시오.

**B-1. 면과 잉크** — 대표색과 **무관한** 따뜻한 무채색입니다. 기관이 색을 무엇으로 바꾸든
이 값들은 그대로여서 화면이 무너지지 않습니다.

```
--surface-work  #f7f6f3   왼쪽, 질문하고 입력하는 곳
--surface-zone  #e4e1db   가운데, 서식이 놓이는 바닥
--surface-rail  #f1f0ec   오른쪽, 안내 기둥
--surface-head  #fbfaf7   상단 바
--paper         #fff      종이 자체
--paper-shadow  0 2px 6px rgba(0,0,0,.06), 0 14px 34px rgba(0,0,0,.10)
--ink           #1a1c1f   본문
--ink-muted     #5b626c   보조   ⚠️ 이보다 더 옅게 하지 마십시오(고령자 가독성)
--border        #d2cfc9   기본선
--border-strong #b9b6b0   입력칸·카드 테두리
```

**B-2. 글자 크기** — 일반 / 크게 보기 두 벌입니다.

```
                일반    크게
--fs-question   34px    40px   시민에게 말하는 큰 질문
--fs-lead       21px    24px   입력칸에 치는 글자
--fs-label      18px    21px   항목 라벨
--fs-card       20px    23px   선택 카드 제목(시민의 말)
--fs-card-sub   15px    17px   선택 카드 보조(행정명칭·설명)
--fs-body       17px    19px   본문
--fs-help       17px    19px   「왜 묻는지」
--fs-sum      16.5px  18.5px   최종 확인 요약 줄
--fs-small    13.5px    15px   행정적 보조 설명
--fs-rail-num   33px    38px   진행 큰 숫자
--fs-rail-head  15px    17px   안내 기둥 머리
--fs-rail-item13.5px  15.5px   안내 기둥 항목
--fs-rail-note12.5px    14px   안심 안내 본문
--fw-bold 700 · --fw-heavy 800 · --ls-tight -.035em (큰 질문에만)
```

**B-3. 둥글기 · 그림자 · 여백** — 이미 정리돼 있습니다. **고칠 것이 있을 때만** 적어 주십시오.

```
--r-xs 4 / --r-sm 8 / --r-md 10 / --r-lg 12 / --r-xl 18 / --r-pill 999
--shadow-lift  0 4px 20px rgba(0,0,0,.4)      떠 있는 것
--shadow-modal 0 20px 60px rgba(0,0,0,.35)    모달
--sp-1 4 / --sp-2 8 / --sp-3 12 / --sp-4 16 / --sp-5 22 / --sp-6 30
```

**B-4. 상태색** — 손대실 수 있습니다.

```
--warn   #a12727 / face #fdecec / line #f5b5b5   ⚠️ 실제 오류·진행불가에만 씁니다
--notice #7a5600 / face #fff8e6 / line #ffe19a   중요하지만 위험은 아닌 안내(갈색 계열)
--focus-face / --focus-line                       ⛔ 대표색 파생입니다. 고정색으로 바꾸지 마십시오
--marker-sign rgba(255,232,0,.55)                 ⛔ 인쇄물입니다. 대상이 아닙니다
```

## 5. 답변 형식 — **이 형식으로만** 주십시오

⛔ **CSS 파일·HTML·React 컴포넌트·이미지 시안을 주지 마십시오.** 붙일 자리가 없습니다.
이 프로젝트는 빌드 도구 없는 자체완결 HTML이고, 값은 **토큰 블록 한 곳**에서만 바뀝니다.

```markdown
## 요약
(3줄 이내. 무엇을 바꿨고 왜인지)

## 먼저 고칠 것 셋
1. …
2. …
3. …

## 값
| 토큰 | 지금 | 제안 | 왜 |
|---|---|---|---|
| --dur-base | (없음) | 200ms | … |
| --surface-zone | #e4e1db | (그대로) | … |

## 동작 배정          ← 과제 A 일 때만
| # | 동작 | 쓸 토큰 | 왜 |
|---|---|---|---|
| 1 | 카드 hover | --dur-quick + --ease-out | … |
| 9 | 개인정보 덮개 | **넣지 않음** | … |

## 넘기지 못한 것
(이 문서의 제약 때문에 제안하지 못했지만 짚고 싶은 것. 없으면 「없음」)
```

- **토큰 이름을 그대로** 써 주십시오. 이름이 다르면 저희가 못 붙입니다.
- 「왜」는 **한 줄**이면 됩니다. 다만 **이 용도(서서 보는 민원실 키오스크·고령자·터치)에
  근거해야** 합니다. 「요즘 이렇게 합니다」는 근거로 쓸 수 없습니다.

## 6. 이미 내린 결정 — ⛔ 뒤집지 마십시오

| | |
|---|---|
| **대기 화면을 따로 두지 않습니다** | 첫 화면이 스스로 시연합니다. 별도 대기 화면·캐러셀·시정홍보 제안은 받지 않습니다 |
| **카드를 눌러도 바로 넘어가지 않습니다** | 그 자리에서 펼쳐 설명·준비물·[작성 시작]을 냅니다 |
| **첫 화면에 아무것도 골라져 있지 않습니다** | 종이 자리에 「서식을 골라 주세요」가 옵니다 |
| **종이의 선명도가 「어디까지 정해졌는가」입니다** | 안 고름=빈 윤곽 → 시연·hover=**실루엣** → 고름=실제 서식이되 흰 베일로 살짝 흐림 → 작성=또렷. ⛔ 실제 서식을 시연·hover 에 쓰지 않습니다 |
| **hover 에만 의존하지 않습니다** | 터치에는 hover 가 없습니다. hover 로만 아는 정보·기능은 금지입니다 |
| **크기는 터치 기준입니다** | 큰 표적은 마우스에서도 문제없지만 그 반대는 성립하지 않습니다 |
| **빨강은 실제 오류에만** | 개인정보 안내·인쇄 안내·정상적인 미입력에는 쓰지 않습니다 |
| **크게 보기를 켜면 종이는 오히려 작아집니다** | 버그가 아니라 받아들인 결과입니다. 목적이 종이 확대가 아니라 조작 UI 접근성입니다 |

## 8. 지난 의뢰에서 실제로 겪은 함정

1. **컴포넌트를 지어내 옵니다.** 지난번 시안은 화면에 없는 메뉴·아이콘·스텝 표시를 그려
   왔습니다. 결국 **비례·여백·정렬만** 쓸 수 있었습니다. 없는 것을 만들지 마십시오.
2. **한 색에 두 뜻을 줍니다.** 「지금 적는 칸」과 「여기 서명하세요」에 같은 노랑을 쓰자는
   제안이 있었습니다. 뒤엣것은 **인쇄물**이라 섞으면 안 됩니다.
3. **대표색을 파랑으로 전제합니다.** 배포본 하나를 여러 기관이 씁니다.
4. **값 대신 분위기를 줍니다.** 「더 모던하게」는 저희가 붙일 수 없습니다.

## 9. 답을 고르는 기준 (의뢰하는 쪽이 읽는 곳)

받은 답 셋을 나란히 놓고 **아래 다섯으로 채점**하십시오. 앞의 셋에서 떨어지면 나머지는 볼 것도 없습니다.

| # | 기준 | 떨어지면 |
|---|---|---|
| 1 | **토큰 이름을 그대로 썼는가** | 붙일 수 없습니다. 탈락 |
| 2 | **대표색을 특정 색으로 전제하지 않았는가** | 다른 기관에서 무너집니다. 탈락 |
| 3 | **인쇄물·레이아웃을 건드리지 않았는가** | 접수처 스캐너가 못 읽습니다. 탈락 |
| 4 | **「왜」가 이 용도에 근거하는가** | 트렌드 근거는 6개월 뒤 다시 흔들립니다 |
| 5 | **바꾸자는 곳이 몇 군데인가** | 전부 바꾸자면 그건 **다듬기가 아니라 재설계**입니다. 지금 단계가 아닙니다 |

⚠️ **셋을 섞지 마십시오.** 하나를 고르고, 나머지에서 **명백히 나은 항목만 골라 옮기십시오.**
섞으면 값 사이의 관계(대비·리듬)가 깨집니다.

⚠️ 고른 뒤에는 **화면 갈무리 전후를 반드시 대조**하십시오. 값 하나가 9개 화면에 퍼집니다.
