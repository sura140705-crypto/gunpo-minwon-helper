# 군포시 민원서식 작성도우미

## DESIGN PHILOSOPHY

> **어려운 행정서식을 시민이 이해하기 쉬운 질문으로 바꾸고,\
> 그 답을 실제 종이서식의 정확한 위치에 연결한다.**

이 서비스의 목적은 종이 민원서식을 없애는 것이 아니다.

기존 법정서식과 민원처리 절차를 존중하면서, 시민이 서식을 이해하고
작성하는 과정에서 겪는 어려움을 디지털 기술로 줄이는 것이 목적이다.

따라서 이 서비스는 새로운 전자민원 시스템이나 전용 키오스크를 만드는
것이 아니라, **기존 PC와 기존 종이서식 사이에 놓이는 가볍고 범용적인
작성 보조도구**를 지향한다.

------------------------------------------------------------------------

# 1. Product Metaphor

## Quiet Paper Desk

이 서비스의 기본적인 공간적 은유는 **"조용한 민원 작성 책상"**이다.

시민이 민원실 책상에 신청서를 펼쳐 놓고 작성하는데, 옆에서 누군가 어려운
부분을 하나씩 쉬운 말로 설명해 주는 상황을 디지털 화면으로 옮긴다.

화면은 웹사이트, 행정업무 시스템, 전자민원 포털보다 **실제 종이를
중심으로 차분하게 작성하는 공간**처럼 느껴져야 한다.

### DO

-   충분한 여백을 둔다.
-   실제 서식을 중요한 시각 요소로 사용한다.
-   한 번에 필요한 정보에 집중시킨다.
-   차분한 Neutral Surface를 사용한다.
-   사용자가 해야 할 행동은 명확하게 보여준다.

### DON'T

-   화면을 카드와 박스로 가득 채우지 않는다.
-   대시보드처럼 만들지 않는다.
-   강한 그림자, **큰 면적의 장식적 Gradient**, Glass effect를 사용하지 않는다.
    좁은 면적의 기관색 Accent는 허용하며, 단색화 여부는 최종 Visual Design
    단계에서 판단한다.
-   여러 색을 장식 목적으로 사용하지 않는다.
-   "디지털 기술을 보여주기 위한 UI"를 만들지 않는다.

------------------------------------------------------------------------

# 2. Paper First

## 종이가 주인공이다

최종 결과물은 데이터가 아니라 **민원인이 실제로 제출할 수 있는
신청서**다. 실제 민원서식은 단순한 Preview가 아니라 사용자가 무엇을
작성하고 자신의 답이 어디에 들어가는지 이해하게 하는 **핵심
인터페이스**다.

**LEFT --- 질문하고 입력하는 곳**\
**CENTER --- 실제 신청서**\
**RIGHT --- 진행과 참고정보**

주변 UI는 중앙 Paper보다 시각적으로 앞서지 않는다.

------------------------------------------------------------------------

# 3. Ask, Don't Form

## 서식을 해석시키지 말고 질문한다

시민에게 행정서식 구조를 이해하도록 요구하지 않는다.

`신청인 구분`보다 **"누구의 여권을 신청하시나요?"**라고 묻는다.\
`공동친권자`보다 **"다른 한 분도 함께 적으시겠어요?"**라고 묻는다.

시민은 자신의 상황에 대해 답하고, **행정서식으로 번역하는 일은 시스템이
담당한다.**

> Citizen Language → System Translation → Administrative Form

정확한 행정용어가 필요한 경우에는 유지하되 시민이 이해할 수 있는 설명을
먼저 제공한다.

------------------------------------------------------------------------

# 4. One Decision at a Time

## 한 번에 하나의 판단

복잡한 신청서 전체를 한꺼번에 작성하도록 요구하지 않는다. 현재 필요한
판단 하나를 명확하게 제시하고, 조건에 해당하지 않는 질문은 가능하면
보여주지 않는다.

**질문 → 답변 → 서식 반영 → 다음 질문**

복잡한 서식을 **작은 의사결정의 연속**으로 바꾸는 것이 핵심이다.

------------------------------------------------------------------------

# 5. Show Where It Goes

## 내가 적는 내용이 어디로 가는지 보여준다

왼쪽에서 질문할 때 중앙 Paper의 실제 기재 위치를 함께 보여준다.

현재 작성 위치는 강한 테두리나 번쩍이는 효과보다 **그 칸을 은은하게 짚어 주는
Current Focus 표현**을 우선한다.

종이 위의 표시는 **두 가지**이며 서로 섞지 않는다.

> **Current Focus** = 지금 작성하는 실제 위치 · 화면 전용 · 기관 대표색 파생 저채도\
> **Print Marker** = 출력 후 시민이 직접 서명·날인·기재할 위치 · Amber/Yellow · 인쇄물

한 색이 두 뜻을 갖게 하지 않는다. Current Focus에 Amber를 쓰면 화면의 노랑은
"지금 적는 칸", 종이의 노랑은 "여기 서명"이 되어 의미가 무너진다.

두 표시 모두 장식색이 아니며 남용하지 않는다.

------------------------------------------------------------------------

# 6. Plain Language

## 행정은 정확하게, 설명은 쉽게

행정서식의 정확성을 유지하면서 시민에게 설명하는 언어를 쉽게 만든다.

문장은 짧게 쓰고 한 문장에는 가능한 한 하나의 행동만 담는다. 기관
관점보다 시민의 행동을 중심으로 쓰며 가능하면 설명보다 예시를 사용한다.

지양: `해당 여부를 선택하여 주시기 바랍니다.`\
지향: `누구의 여권을 신청하시나요?`

지양: `기재사항을 입력하여 주십시오.`\
지향: `이름을 적어 주세요.`

------------------------------------------------------------------------

# 7. Progressive Assistance

## 필요한 순간에 필요한 만큼만 돕는다

모든 설명을 처음부터 보여주지 않는다.

**질문 → 짧은 설명 → 예시 → 직원 도움**

설명을 많이 제공하는 것보다 **필요한 순간에 정확한 도움을 제공하는
것**을 우선한다.

------------------------------------------------------------------------

# 8. Human Escape is a Feature

## 직원에게 묻는 것은 실패가 아니다

민원 업무에는 시스템만으로 판단하기 어려운 상황이 존재한다.

`잘 모르겠어요 — 직원에게 여쭤볼게요`는 오류처리가 아니라 **정상적인
사용자 경로 중 하나**다.

다만 **공통 UI 요소로 모든 질문에 자동 삽입하지 않는다.** 충분한 설명과
판단기준을 제공한 뒤에도 **판단이 어려운 실제 업무 지점**에서만 선택적으로
제공한다.

-   시민의 법적·행정적 판단이 실제로 필요한 화면 → 제공한다
-   사실을 기재하는 화면(성명·연락처·주소) → 제공하지 않는다
-   읽고 확인하는 화면(안내·준비물) → 제공하지 않는다
-   시스템이 이미 결정할 수 있는 화면 → 제공하지 않는다

어디에나 있으면 "여기서 막힐 수도 있겠구나"라는 신호가 되고, 정작 판단이
필요한 자리에서 눈에 띄지 않는다.

직원 판단이 필요한 경우 가능한 한 개인정보 전체가 아닌 **비식별 코드
또는 최소한의 상황정보**로 연결한다.

------------------------------------------------------------------------

# 9. Prevent Failure Before Validation

## 틀리고 나서 알려주기보다 틀리지 않게 한다

좋은 오류 메시지보다 오류가 발생하지 않는 구조를 우선한다.

-   작성 전 준비물 확인
-   쉬운 예시
-   입력 형식 안내
-   조건에 맞는 질문만 표시
-   현재 작성 위치 표시
-   마지막 전체 확인

`잘못 입력하셨습니다.`보다 `숫자 13자리를 확인해 주세요.`처럼 **다음
행동을 알려준다.**

무엇을 쓰는지만큼 **언제 띄우는지**가 중요하다.

-   사용자가 아직 아무 행동도 하지 않은 상태에서 Validation을 표시하지 않는다.
-   필수 입력 누락은 **다음 진행을 시도했을 때만** 알린다.
-   값의 형식이 실제로 틀린 경우는 그 자리에서 바로 알려도 된다.

아직 적지 않은 것은 실수가 아니다. 화면에 들어서자마자 경고가 떠 있으면
시민은 자신이 무언가 잘못한 줄로 안다.

------------------------------------------------------------------------

# 10. Context Rail

## 오른쪽은 변하지 않는 참고 공간이다

오른쪽은 광고나 추가 기능 공간이 아니라 현재 민원에 필요한 **지속적인
참고정보**를 제공한다.

-   현재 작성 진행상황
-   전체 작성 단계
-   준비물
-   계속 기억해야 할 사항
-   개인정보·공용 PC 안내

질문이 바뀔 때마다 정보 전체가 바뀌지 않는 **안정적인 Reference
영역**이어야 한다.

------------------------------------------------------------------------

# 11. Privacy without Fear

## 개인정보를 보호하되 시민을 겁주지 않는다

개인정보 보호는 **색보다 구조와 동작으로 구현한다.**

-   개인정보 서버 미저장
-   세션 종료 시 입력내용 삭제
-   일정시간 자리비움 시 자동 초기화
-   인쇄 후 초기화
-   다음 사용자에게 이전 내용 미노출

지속 안내는 오른쪽 Reference 영역에 제공하고, 중요한 문장은 **갈색·짙은
Neutral 계열의 굵은 글씨**(Notice)로 강조한다.

> **Red는 실제 오류 · 진행불가 · 임박한 파괴적 상태에 제한한다.**

개인정보 일반안내, 인쇄 일반안내, 정상적인 미입력 상태에는 Red를 쓰지 않는다.
중요하지만 위험이 아닌 것은 Notice로 낸다. 다만 **실제 출력 실패나 접수 반려로
이어지는 핵심 문구**는 Notice 안에서 Warning emphasis를 줄 수 있다 — 상자 전체를
Red로 만들지는 않는다.

> **Warning color is semantic, not decorative.**

------------------------------------------------------------------------

# 12. Physical--Digital Bridge

## 화면에서 끝나는 서비스가 아니다

완료는 `제출` 버튼이 아니라 **정확하게 작성된 실제 신청서가 출력되는
순간**까지다.

-   실제 신청서 Preview
-   실제 크기 출력
-   정확한 Print setting
-   직접 서명해야 하는 위치
-   출력물 수령 안내
-   인쇄 후 개인정보 초기화

**디지털은 종이를 더 쉽게 완성하기 위한 도구다.**

------------------------------------------------------------------------

# 13. Accessibility by Default

## 특정 계층을 위한 별도 UI가 아니라 좋은 기본 UI

고령자나 디지털 취약계층을 별도의 사용자처럼 취급하지 않는다.

-   큰 질문
-   읽기 쉬운 본문
-   충분한 명도 대비
-   넓은 클릭 영역
-   명확한 버튼
-   쉬운 문장
-   충분한 여백

화면 보기는 **일반 / 크게 보기** 두 가지로 단순화한다.

전체 화면 Zoom이나 Paper의 단순 확대가 아니라, **UI의 읽기와 조작 편의를
높이는 Responsive Layout Mode**다.

-   LEFT 질문 영역의 **폭**과 Typography를 함께 키운다
-   Input / Choice / Button을 함께 키운다
-   RIGHT Context Rail의 **구조와 폭은 유지**하고 Typography만 키운다
-   CENTER Paper는 **바뀐 영역 안에서 가능한 최대 크기**를 유지한다(fit-to-area).
    고정 배율을 먼저 정하지 않는다.
    LEFT가 넓어진 만큼 **Paper는 오히려 작아질 수 있으며 이는 의도된 결과다** —
    서식을 크게 보는 길은 Paper 확대·스크롤과 미리보기로 따로 있다
-   기존 Paper 확대·스크롤 기능은 그대로 둔다
-   자유로운 Panel Drag / Resize는 제공하지 않는다

컬럼 비율은 실제 화면을 보고 미세조정할 수 있도록 **Token으로 관리한다.**

------------------------------------------------------------------------

# 14. Calm, Not Empty

## 조용하지만 허전하지 않게

Minimal UI 자체가 목적은 아니다. 필요한 정보는 충분히 제공하되 시각적
소음을 줄인다.

**현재 질문 → 선택 또는 입력 → Paper의 대응 위치 → 다음 행동 → 필요할 때
Reference**

디자인은 이 시선 순서를 방해해서는 안 된다.

------------------------------------------------------------------------

# 15. Color Philosophy

## 색에는 각각 하나의 역할을 부여한다

-   **Institution Accent**: 군포시/기관 Identity와 Primary Action.
-   **Paper**: White / Off-white.
-   **Background**: Warm Neutral.
-   **Ink**: Near Black.
-   **Muted Ink**: 설명과 Secondary information. 가독성을 해칠 정도로
    대비를 낮추지 않는다.
-   **Current Focus**: 기관 대표색에서 파생한 저채도. 지금 작성 중인 Paper
    위치. **화면 전용.** 대표색이 바뀌면 함께 따라온다.
-   **Print Marker**: Amber/Yellow. 출력 후 시민이 직접 서명·날인·기재할
    위치. **인쇄물의 일부.** Current Focus와 색을 공유하지 않는다.
-   **Notice**: 짙은 갈색·Neutral 계열. 중요하지만 위험은 아닌 안내.
-   **Warning**: Red 계열. 실제 오류·진행불가·임박한 파괴적 상태에만 사용.

------------------------------------------------------------------------

# 16. Typography is the Voice

## 글자 크기와 굵기가 설명의 일부다

큰 글씨는 시민에게 말하는 언어이고 작은 글씨는 행정적 설명과 보조정보다.

Font 종류를 여러 개 사용하지 않고 가능한 한 하나의 안정적인 Sans-serif
Family 안에서 크기와 Weight로 hierarchy를 만든다.

------------------------------------------------------------------------

# 17. Interaction

## 움직임은 상태를 설명할 때만 사용한다

Animation은 화려함이 아니라 의미가 있는 경우에만 사용한다.

-   현재 Paper 위치를 알려줄 때
-   단계가 이동했음을 알려줄 때
-   Idle 화면에서 시스템이 작동 중임을 보여줄 때

빠른 움직임, 반복 Pulse, 여러 요소의 동시 Animation은 피한다.

`prefers-reduced-motion`은 **공통 UI 규칙으로 포함한다.** 다만 이를 위해 기존
기능을 흔드는 대규모 변경은 하지 않는다.

------------------------------------------------------------------------

# 18. Consistency, Not Uniformity

## 모든 서식이 같을 필요는 없지만 사용법은 같아야 한다

각 민원서식의 구조는 다르지만 시민이 익혀야 하는 **사용 방법은 같게
유지한다.**

**서식 선택 → 준비 → 쉬운 질문 → 실제 Paper 반영 → 확인 → 인쇄**

새로운 서식이 추가되어도 사용법을 다시 배울 필요가 없어야 한다.

------------------------------------------------------------------------

# 19. Low-cost & Universal

## 특정 장비에 종속되지 않는다 — Input-Agnostic, Touch-Friendly

핵심 목표 중 하나는 **누구나 쉽게 도입할 수 있는 범용성**이다.

전용 키오스크나 고가 특수장비를 전제로 하지 않는다. 일반적인 PC, 모니터,
키보드, 마우스, 프린터 환경 및 기존 민원실 PC나 유휴·재사용 PC에서도
구동 가능한 수준을 지향한다.

**"일반 PC 지원"은 마우스 전용을 의미하지 않는다.**

> **Input-Agnostic, Touch-Friendly**

-   터치 · 마우스 · 물리키보드에서 **모두** 사용 가능해야 한다
-   **크기는 큰 조작영역을 기본으로 한다.** 큰 표적은 마우스에서도 문제가
    없지만 그 반대는 성립하지 않는다
-   hover는 보조 효과로만 사용한다. **hover에만 의존하는 정보나 기능은
    만들지 않는다**
-   문구도 특정 입력장치를 전제하지 않는다

향후 Touch Display, Digital Pad 등이 도입되더라도 **기본 설계가 특정
장비에 종속되어서는 안 된다.**

------------------------------------------------------------------------

# 20. Prototype for Expansion

## 군포만의 특수 시스템이 아니라 확장 가능한 모델

현재 구현이 모든 지자체 민원업무의 정답이라고 가정하지 않는다. 군포시는
하나의 실행 가능한 방법을 먼저 구현하고 검증한다.

더 좋은 업무흐름, 표준안 또는 기술방식이 제시된다면 수용할 수 있어야
한다.

가능하면 다음을 분리한다.

**Design System / Form Definition / Question Flow / Mapping Logic /
Print Logic**

향후 서식 추가 및 다른 기관 적용을 쉽게 한다.

------------------------------------------------------------------------

# 21. Design System before Page Design

## 화면 하나가 아니라 규칙을 만든다

여권 화면을 **첫 번째 Reference Implementation**으로 삼아 다른 서식에도
적용할 수 있는 디자인 시스템을 만든다.

공통 요소는 Token과 Component로 관리한다.

Surface, Paper, Ink, Muted Ink, Institution Accent, **Current Focus,
Print Marker**, Notice, Warning, Border, Radius, Shadow, Spacing,
Typography, Question, Choice, Input, Help, Validation, Navigation,
Context Rail, Modal, Print state.

새로운 서식을 만들 때 새로운 디자인을 발명하지 않는다.

------------------------------------------------------------------------

# 22. Main / Idle Philosophy

## 대기화면은 광고판이 아니라 사용해도 된다는 신호다

공용 PC 앞에서 시민이 **"이걸 내가 만져도 되는 건가?"**라고 느끼지 않게
한다.

> **이것은 시민이 지금 사용할 수 있는 도구다.**

Idle 화면은 복잡한 Carousel이나 시정홍보 전광판처럼 만들지 않는다. 실제
작성 경험과 연결되는 **Paper와 Print Marker**를 Signature Visual로 사용할 수
있다(Idle은 작성 중이 아니므로 Current Focus는 쓰지 않는다).

대표 문장:

> **질문에 답하면, 신청서가 완성됩니다.**

CTA — 입력장치를 전제하지 않는 표현을 쓴다(§19):

> **아무 곳이나 눌러 시작하세요.**

Idle에서 실제 서비스로 전환될 때 다른 제품으로 바뀐 것처럼 느껴지지
않아야 한다.

------------------------------------------------------------------------

# 23. Trust before Wow

## 공공서비스에서는 신뢰가 시각적 화려함보다 우선한다

시민에게 중요한 것은 다음이다.

-   무엇을 해야 하는지 알 수 있는가
-   내가 입력한 내용이 어디에 들어가는지 알 수 있는가
-   실수하지 않을 수 있는가
-   개인정보가 안전한가
-   막히면 직원에게 물어볼 수 있는가
-   제대로 출력되는가

> **좋은 디자인은 시민이 디자인을 의식하는 것이 아니라 신청서를 어렵지
> 않게 완성하게 만드는 것이다.**

------------------------------------------------------------------------

# 24. Decision Priority

## 디자인 판단이 충돌할 경우

1.  시민이 이해할 수 있는가
2.  시민이 실수하지 않는가
3.  실제 행정서식과 정확하게 연결되는가
4.  개인정보와 공용 PC 환경에서 안전한가
5.  필요한 경우 직원에게 자연스럽게 연결되는가
6.  고령자·디지털 취약계층도 사용할 수 있는가
7.  다른 서식과 기관으로 확장할 수 있는가
8.  시각적으로 일관적인가
9.  아름다운가

> **미적 완성도를 위해 1\~7을 희생하지 않는다.**

------------------------------------------------------------------------

# Final Principle

이 서비스가 지향하는 것은 **"종이를 디지털로 없애는 것"이 아니다.**

**"어려운 종이를 시민이 쉽게 완성하게 하는 것"이다.**

그리고 이를 **고가의 장비나 대규모 시스템 없이도 구현할 수 있어야
한다.**

따라서 우리가 만드는 것은 하나의 화려한 키오스크가 아니라,

> **쉬운 질문 + 실제 Paper + 정확한 Mapping + 사람의 도움 + 안전한
> 인쇄**

라는 단순한 원칙으로 작동하는 **범용적인 민원서식 작성 경험**이다.
