## 1. Highlighter — 두 가지를 갈라 부른다

철학 §5·§15 는 「Highlighter = Muted Amber = 지금 작성하는 위치」라고 한다.
**그 색에는 이미 임자가 있다.**

| | 무엇 | 색 | 인쇄 |
|---|---|---|---|
| **Current Focus** (`.ovhl`) | 지금 작성 중인 Paper 위치 | 대표색에서 파생한 **저채도** | ❌ 화면 전용 |
| **Print Marker** (`.ovhi`·`.csign-hl`) | 인쇄 후 **직접 서명·날인·기재할** 위치 | 노랑 | ✅ **인쇄물** |

- Current Focus 를 노랑/Amber 로 바꾸지 않는다. 화면의 노랑=지금 적는 칸,
  종이의 노랑=여기 서명 이 되어 **한 색이 두 뜻**을 갖는다.
- 대표색 파생을 유지하면 기관이 색을 바꿔도 Focus 가 따라오는 이점이 남는다.
- ⛔ Print Marker 는 인쇄물이다. 색·투명도를 바꾸면 `verify-print.py` 기준선을 갱신해야 한다.

## 2. 입력장치 — Input-Agnostic, Touch-Friendly

철학 §19 의 「일반 PC 지원」은 **마우스 전용을 뜻하지 않는다.**

- 터치·마우스·물리키보드에서 **모두** 쓸 수 있어야 한다.
- **크기는 터치 기준을 유지한다.** 큰 표적은 마우스에서도 문제가 없지만 그 반대는 성립하지 않는다.
- hover 는 **보조 효과로만** 쓴다. ⛔ hover 에만 의존하는 정보·기능은 금지.

## 3. Red — 언제 쓰는가

> Red 는 **실제 오류 · 진행불가 · 임박한 파괴적 상태**에 제한한다.

- ⛔ 개인정보 일반안내, 인쇄 일반안내, **정상적인 미입력 상태**에는 쓰지 않는다.
- **표시 시점 규칙**: 사용자가 아직 아무 행동도 하지 않았는데 Validation 을 띄우지 않는다.
  필수 입력 누락은 **다음 진행을 시도했을 때만** 알린다.
- 위험은 아니지만 중요한 안내는 **Notice**(짙은 갈색 계열)로 낸다.

## 4. Gradient — 전면 금지가 아니다

철학 §1 DON'T 는 **큰 면적의 장식적 Gradient** 를 금하는 것으로 읽는다.
지금의 제한적인 기관색 Accent(상단 바 3px 띠 등)는 **당장 제거하지 않는다.**
단색화 여부는 최종 Visual Design 단계에서 다시 판단한다.

## 5. Human Handoff — 어디에 두는가

모든 질문에 똑같이 붙이는 방식은 지양한다.
**설명과 판단기준을 준 뒤에도 판단이 어려운 실제 업무 지점**에서만 선택적으로 낸다.
사실을 적는 화면(성명·연락처 등)에는 붙이지 않는다.

## 6. 신규 기능의 자리

| | 언제 |

| 일반 / 크게 보기 | **여권 Reference UI 단계** |

## 6-1. 크게 보기에서 Paper 가 작아지는 것 — **받아들인다**

구현 후 실측에서 드러난 것이다. 크게 보기를 켜면

| | 일반 | 크게 |
|---|---:|---:|
| LEFT 질문면 | 794px | **949px** |
| CENTER Paper | 794×1122 | **667×943** |
| RIGHT 기둥 | 252px | 252px (글자만 +15%) |

**LEFT 를 넓히면 CENTER 가 그만큼 줄어든다.** 「크게 보기」를 켰는데 종이는 작아지는
셈이라 §2 Paper First 와 부딪히는 것처럼 보인다.

> **그대로 둔다**(2026.08.24 결정).
> 크게 보기의 목적은 **PDF 확대가 아니라 질문·입력·조작 UI 의 접근성**이다(§13).
> 서식을 크게 보는 길은 이미 따로 있다 — 기존 Paper 확대·스크롤과 [미리보기].

⛔ 이것을 「버그」로 보고 되돌리지 마라. 되돌리려면 이 문단을 먼저 고쳐라.
⚠️ 조정이 필요하면 **`--cols` 계열 토큰만** 만지면 된다(`engine/base.html` 의 `html.big`).
   실물 1920×1080 을 보고 비율만 바꾸는 것이 의도된 조정 경로다.
