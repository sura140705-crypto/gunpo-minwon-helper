# 디자인 검토 2회차 — 메인화면과 화면 초기화 (2026.08.23 기준)

이 문서는 **1회차 의뢰서([`README.md`](README.md))의 후속**입니다. 그 문서를 먼저 읽어 주십시오.
다만 그 뒤로 코드가 크게 움직여서, **1회차 문서 중 일부는 이미 낡았습니다.**
어디가 낡았는지를 §1~§3 에 적었습니다. 새로 봐 주셨으면 하는 것은 §5~§6 입니다.

> 검토를 도와주시는 분과 저희 사이에 **서로 다른 그림을 갖고 있을 수 있어** 만든 문서입니다.
> 「지금 코드가 실제로 어떤 상태인가」를 사실대로 적는 것이 목적입니다.

## 1. 1회차 이후 무슨 일이 있었나

**2026.08.21 에 여권 도우미(8종 중 1종)를 통째로 갈아엎었습니다.**

1회차 의뢰서 §6 질문 1 은 「8종을 하나의 조작법으로 묶는다면 어느 쪽으로 가야 합니까」였습니다.
저희는 **그 답을 기다리지 못하고 여권을 먼저 개편했습니다.** 시연 일정 때문입니다.
그 결과 지금은 **여권 화면이 사실상의 기준안 노릇**을 하고 있습니다 — 의도한 순서는 아니었습니다.

그래서 이번 검토의 실제 질문은 이렇게 바뀌었습니다:

> **여권에서 만든 조형 언어를 메인화면(허브)으로 가져가는 것이 맞습니까?**
> 아니면 여권 쪽을 되돌려서라도 다른 기준을 잡아야 합니까?

되돌리는 답도 받아들일 수 있습니다. 아직 7종이 안 바뀌었으니 지금이 마지막 기회입니다.

## 2. 새 여권 화면이 어떻게 생겼나 (지금의 기준안)

> 📷 **갈무리는 `shots/pass-01` ~ `pass-08` 입니다** — 2026.08.24 에 다시 뽑았습니다(§4 참조).
> 아래 그림은 그 화면의 뼈대만 글로 옮긴 것입니다.

화면을 **세 영역**으로 나눴습니다. 종전의 「배경 위에 뜬 흰 카드」를 버렸습니다 —
손에 쥐는 화면의 은유라, 서서 쓰는 큰 키오스크에서는 화면 한복판에 작은 종이가 떠 있는 꼴이었습니다.

```
┌──────────────────────────── 상단 바 (min-height 74px) ────────────────────────────┐
│  로고 · 기관명        │  지금 쓰는 서식 이름  │        도구(처음으로 등)          │
├───────────────────────┼───────────────────────┼───────────────────────────────────┤
│                       │                       │                                   │
│   질문면              │   서식(Paper)         │   안내 기둥                       │
│   Writing Desk        │   실제 인쇄될 종이    │   Companion Rail                  │
│   --work #f7f6f3      │   --zone #e4e1db 바닥 │   --rail #f1f0ec                  │
│                       │                       │                                   │
│   질문 34px           │   값이 얹혀 보임      │   진행(큰 숫자 33px)              │
│   카드 두 칸 격자     │   (인쇄물 = 이 영역)  │   묶음 목록(되돌아가기 가능)      │
│   글자칸 64px         │                       │   준비물 · 안심 안내 · 이용 안내  │
│                       │                       │                                   │
└───── minmax(0,1fr) ───┴─── minmax(0,1.08fr) ──┴────────── 252px 고정 ─────────────┘
```

- 폭 배분 : `minmax(0,1fr) minmax(0,1.08fr) 252px` — 1600px 이하에서는 기둥이 `214px` 로 좁아집니다.
- **세로 화면(1080×1920)** 은 질문을 위·서식을 아래로 눕히고, 안내 기둥은 **머리맡 가로 띠**로 접습니다
  (그때는 준비물을 감춥니다 — 「작성 전 준비」 화면에서 한 번 안내하므로).
  1회차에서 「아는 문제 7번」으로 올렸던 세로 잘림은 **여권에서는 해결됐습니다.**

### 주요 수치

| | 값 |
|---|---|
| 질문 | 34px / 800 / `letter-spacing:-.035em` / `max-width:640px` |
| 「왜 묻는지」 | 16.5px, 상자 없이 **왼쪽 선 3px** 만 (상자가 많으면 질문이 묻힙니다) |
| 터치 카드 | 두 칸 격자 `1fr 1fr`, `min-height:132px`, gap 14px, `max-width:700px` |
| 카드 홀수 마지막 | 한 줄을 다 씁니다 — 대개 그 자리에 오는 「잘 모르겠습니다」가 눈에 띕니다 |
| 글자 입력칸 | 높이 64px / 글자 21px / 700 |
| 항목 라벨 | 18px / 800 |

### 새로 들어온 색 — 대표색과 **무관한** 중립 4종

1회차 §4 에서 「특정 색을 전제로 한 디자인은 쓸 수 없다」고 말씀드렸는데, 그것에 대한
저희 쪽 답이 이것입니다. **기관 대표색은 강조에만 쓰고, 화면의 바탕은 대표색과 끊었습니다.**

```css
--work #f7f6f3   질문을 적는 작업면
--zone #e4e1db   서식이 놓이는 바닥        ← 세 면의 명도를 조금씩 달리해
--rail #f1f0ec   오른쪽 안내 기둥             선을 긋지 않고도 영역이 갈립니다
--head #fbfaf7   상단 바
--line-warm   #d2cfc9      --line-strong #b9b6b0
--hair        rgba(대표색, .16)   ← 기하학적 포인트 선에만
```

기존 대표색 4종(`--blue` `--blue-dark` `--blue-light` `--grad`)은 그대로 있고,
여전히 **한 색에서 계산**합니다(명도 30~55% 로 강제).

### 새로 생긴 화면 셋

- **「작성 전 준비」**(`pass-07`) — 무엇을 들고 와야 하는지. ⛔ 막지는 않습니다(준비물이 없어도 끝까지 작성 가능).
- **「공동친권자」**(`pass-08`) — 미성년 경로에서 법정대리인 2 를 받습니다. 전부 선택입니다.
- **최종 확인의 「수정」 바로가기**(`pass-04`) — 그 자리에서 고치러 갑니다(뒤로만 이동, 검증 우회 없음).

## 5. 이번 검토 대상 ① — **메인화면(허브)**

파일 : `index.html`. 시민이 여기서 서식을 고릅니다. 초기화될 때 돌아오는 곳도 여깁니다.

> 📷 `shots/hub-01-첫화면` · `hub-01-첫화면-세로` · `hub-02-기관색교체`(다른 기관이 대표색을
> 초록으로 바꾸고 여권을 끈 상태). 허브는 개편 전이라 **1회차 갈무리 그대로 유효**합니다.

### 지금 구조

```
상단 바   로고 · "군포시 민원 서식 작성 도우미" · 기관명 · 오늘 날짜
빨간 띠   개인정보 안내 2줄 (공용 PC · 출력물 직접 수령)
hero      "어떤 서식을 작성하시나요?" + 설명 2줄
카드       ┌ 여권 ────────────────┐ 1장
           ├ 가족관계등록 신고 ───┤ 5장 (혼인·출생·사망·개명·이혼)
           ├ 증명서 발급 ─────────┤ 1장
           └ 부동산 ──────────────┘ 1장          모두 8장
           격자 : repeat(auto-fill, minmax(300px,1fr)), gap 16px
           카드 : 아이콘 54px + 제목 19px + 설명 15px + 배지 + "작성하기 →"
하단      이용 안내 5줄
```

- 본문 폭 `max-width:1080px` 가운데 정렬 → **1920 화면에서 양옆이 420px 씩 빕니다.**
- 카드 배지는 「이용 가능」/「준비 중」 두 가지인데, **8종이 다 완성돼 지금은 전부 「이용 가능」**입니다.
- ⚠️ **카드 수는 기관마다 다릅니다.** 그 기관이 취급하지 않는 민원은 카드가 아예 뜨지 않습니다
  (여권은 시·군·구청만 취급). **4장만 남는 기관, 섹션 하나가 통째로 사라지는 기관이 있습니다.**
  카드 8장을 전제한 레이아웃은 쓸 수 없습니다.

### 저희가 문제로 보는 것

1. **여권 새 화면과 조형 언어가 다릅니다.** 허브는 흰 카드 + 파란 계열, 여권은 중립 3면 + 대표색 강조.
   같은 키오스크에서 첫 화면과 다음 화면이 다른 프로그램처럼 보입니다.
2. **1080px 폭.** 1920 에서 좁게 몰려 있습니다(1회차 문제 3번, 아직 그대로).
3. **배지가 정보를 주지 못합니다.** 전부 「이용 가능」이면 없는 것과 같습니다.
4. **어르신이 8장 중에서 고르는 일 자체가 어렵습니다.** 「증명서 발급」과 「가족관계등록 신고」의
   차이를 시민이 알아야 하는 구조입니다. 실제로는 「등본 떼러 왔다」고 오십니다.
5. **아무도 안 쓰는 동안의 화면이 없습니다.** 허브가 그냥 떠 있습니다(§6 과 연결됩니다).

### 세 영역 언어를 허브로 가져갈 때의 문제

여권의 세 영역은 **「서식」이 있어서** 성립합니다. 허브에는 서식이 없습니다.
세 칸 중 가운데가 비는데, 이걸 어떻게 하는 게 좋을지가 이번 검토의 핵심 질문입니다.

| 무동작 **2분 30초** | (아무 표시 없음) |
| **2분 30초 ~ 3분** | 화면 전체를 어두운 막(`rgba(15,23,42,.72)`)으로 덮고 흰 상자를 띄웁니다.<br>「**잠시 후 처음 화면으로 돌아갑니다**」 26px / 800 / 대표색<br>「개인정보 보호를 위해 **30**초 후 입력하신 내용이 모두 지워집니다」 (숫자가 빨강 22px 로 1초마다 줄어듦)<br>[계속 작성하기] 버튼 하나 |
| **3분** | `index.html` 로 이동. 값은 메모리에만 있어 그대로 사라집니다 |

`reset-01` 이 그 경고 화면입니다(갈무리에는 카운트다운이 26초에서 잡혔습니다).

- 활동 감지 : `mousemove` `mousedown` `keydown` `touchstart` `wheel` → 타이머 리셋(경고 중이면 취소).
- ⛔ **허브(`index.html`)에는 이 장치가 없습니다.** 되돌아갈 곳이 자기 자신이고, 입력값도 없어서입니다.

### 인쇄 후 초기화

- **인쇄 직전**에 모달로 안내합니다 — ①개인정보 안내(빨간 상자) ②「여백 없음 · 배율 100%」.
  [취소] [인쇄 창 열기]. → `reset-02`
- **인쇄 창이 닫히면**(`afterprint`) 화면을 거의 불투명하게(`.985`) 덮고
  「🖨️ 인쇄를 보냈습니다 / 출력물을 꼭 챙겨 가세요」를 띄운 뒤 **5초 후** 허브로 갑니다. → `reset-03`
- ⚠️ 브라우저는 「인쇄함」과 「취소함」을 구분해 알려주지 않습니다. **취소해도 초기화됩니다.**
  그래서 인쇄 직전 모달에서 미리 알립니다.

### 관리자가 바꿀 수 있는 값 (환경설정 창, Ctrl+Shift+S)

| 항목 | 선택지 |
|---|---|
| 무동작 대기 | 1분 / **3분(기본)** / 5분 / 10분 |
| 인쇄 후 대기 | 즉시 / 1초 / 3초 / **5초(기본)** / 10초 |

경고 시간 30초는 고정입니다(코드 상수).

### 저희가 문제로 보는 것

1. **경고 모달이 「사고」처럼 생겼습니다.** 어두운 막 + 빨간 카운트다운. 실제 뜻은
   「아직 계신가요?」에 가까운데, 시민이 놀라서 창구에 물으러 오는 일이 있습니다.
2. **30초는 뒤에 사람이 서 있을 때 깁니다.** 앞사람이 자리를 뜬 것이 분명해도 30초를 기다립니다.
3. **3분의 근거가 약합니다.** 가방에서 신분증을 꺼내 번호를 확인하는 동안 3분이 지나기도 하고,
   개인정보 관점에서는 3분도 깁니다. 두 요구가 충돌합니다.
4. **인쇄 후 5초 뒤 강제 이동** — 출력물을 프린터에서 챙기기 전에 화면이 바뀝니다.
   「제대로 인쇄됐는지」를 화면에서 다시 확인할 방법이 없습니다.
4-1. ✅ ~~인쇄 후 덮개(`.985`)가 완전히 가리지 못합니다~~ — **2026.08.24 조치 완료.**
   갈무리(`reset-03`)를 뽑고 나서 알았습니다: 어두운 막 너머로 주민등록번호와 이름이
   흐릿하게 읽혔습니다. 불투명도를 1 로 올렸고, 덮개가 인쇄 CSS 에 걸리지 않아
   실수로 인쇄하면 새까만 페이지가 나가던 것도 함께 막았습니다.
   갈무리를 픽셀로 훑어 **바탕색에서 벗어난 픽셀 0개**임을 확인했습니다.
   ⚠️ 다만 **덮개가 무엇처럼 보여야 하는지**(꺼진 화면인가, 덮인 화면인가)는 여전히
   디자인 질문으로 남습니다(§8-6).
5. **대기 상태의 화면이 없습니다.** 아무도 안 쓰는 동안 허브가 그냥 떠 있습니다.
   민원실에 「이게 뭘 하는 기계인지」 알리는 자리가 없습니다.
6. ⚠️ 이 장치의 코드는 **9곳에 복제**돼 있습니다(엔진 원본 1 + 손작성 3종 + 빌드된 5종).
   디자인을 바꾸면 9곳이 함께 움직여야 합니다 — **한 벌만 주시면 저희가 퍼뜨립니다.**

## 7. 바뀌지 않은 제약 (1회차와 동일)

- ⛔ **인쇄물은 손대지 마십시오.** 정부 별지서식 이미지 위에 **절대좌표**로 값을 얹습니다.
  1pt 밀리면 접수처 스캐너가 못 읽습니다. `verify-print.py` 가 19쪽을 픽셀로 비교해 지킵니다.
  `@media print { … }` 안의 규칙과 서식 이미지는 대상이 아닙니다.
- 색은 **대표색 하나에서 계산**합니다(명도 30~55% 로 강제). 기관마다 다릅니다.
- 글꼴은 `"Malgun Gothic"`. 다른 글꼴을 제안하시려면 **설치 없이 쓸 수 있는지** 같이 알려 주십시오.
- **터치로 고르고, 글자는 물리 키보드로 칩니다.** 화면 키보드는 쓰지 않기로 했습니다(2026.08.13 결정).
  키보드가 없는 자리도 있어서, 그때는 상단 바에 「직원에게 말씀해 주세요」가 뜹니다.
- **오프라인 Electron 설치본**입니다. 외부 CDN·웹폰트·이미지를 쓸 수 없습니다. 아이콘은 전부 이모지입니다.
- 8종 + 허브 **9개 화면에 똑같이 들어가야 하는 블록**이 있습니다(기관별 설정). 글자까지 같아야 합니다.

## 8. 이번에 봐 주셨으면 하는 것

1. **여권의 세 영역 언어를 기준으로 삼는 것이 맞습니까?** 되돌리는 답도 받습니다(§1).
2. **허브를 그 언어로 어떻게 옮깁니까?** 가운데 「서식」 자리가 비는 문제를 어떻게 풀지(§5 끝).
3. **8장(때로 4장)의 카드를 어떻게 묶고 정렬합니까?** 시민은 「등본 떼러 왔다」고 옵니다 —
   행정 분류가 아니라 **시민의 말로 고르게** 하는 안이 있으면 좋겠습니다.
4. **대기 화면(attract)이 필요합니까?** 필요하다면 어떻게 깨어나야 합니까.
5. **초기화 경고를 어떻게 보이게 합니까?** 「사고」가 아니라 「아직 계신가요」로 읽히게.
   30초라는 길이 자체에 대한 의견도 주십시오.
6. **인쇄 후 화면.** 출력물을 챙기게 만들면서, 뒷사람에게는 아무것도 안 보여야 합니다.
7. 1회차 §6 의 질문 중 **3·4·5·7 번은 아직 답을 받지 못했습니다.** 여력이 되시면 함께 봐 주십시오.

## 9. 답을 주시는 방법 (1회차와 같습니다)

- **글(마크다운)로 주셔도 됩니다.** 무엇을 왜 바꾸는지가 제일 중요합니다.
- 구체적인 값이 있으면 좋습니다. `현재-스타일.css` 위에서 고쳐 주시거나
  「이 규칙을 이렇게」 식으로 적어 주셔도 저희가 원본에 옮깁니다.
- 시안 이미지를 주시면 그대로 참고합니다. **다만 인쇄되는 서식 영역은 바꾸지 마십시오.**
- **우선순위를 매겨 주십시오.** 시범운영 중이라 한 번에 다 바꾸기는 어렵습니다.
- 초기화 장치는 **한 벌만** 주시면 됩니다(9곳 복제는 저희가 처리합니다).

> 갈무리에 나오는 이름·주소·번호는 **전부 가상 인물**입니다. 실제 개인정보는 이 리포 어디에도 없습니다.
