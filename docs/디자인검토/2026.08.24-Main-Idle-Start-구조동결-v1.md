# MAIN / IDLE / START — 구조 동결 v1 (2026.08.24)

여권 Reference UI 를 기준으로 **Idle → Main → Start → Writing** 을 하나의 연속된 경험으로
설계하고, 그 **구조·정보위계·전환 규칙**을 여기서 동결한다.

## 이 문서가 동결하는 것 / 하지 않는 것

| 동결한다 | 동결하지 않는다 |
|---|---|
| 상태와 흐름 | 색·명도 |
| 구역(BAR·ASK·PAPER·RAIL)과 배치 | 타이포 세부 수치 |
| 정보 위계 | 질감·그림자·둥글기 |
| Paper Lifecycle | 아이콘 조형 |
| Rail·BAR 규칙 | Generic Paper 의 조형 |
| **무엇이 움직이고 무엇이 남는가** | Idle 시연의 시각 표현 |
| Catalog 스키마 | 시민언어 **최종 문구**(§10 참조) |

> 위 오른쪽 칸은 **Stitch 시안을 받은 뒤** 선별해 반영한다.
> ⛔ 이 문서를 근거로 **Visual Design 을 먼저 구현하지 않는다.**

[`2026.08.24-디자인-결정.md`](2026.08.24-디자인-결정.md) · 동결된 여권 Reference UI

# 1. 상태와 흐름

```
IDLE → MAIN → START → WRITING → REVIEW → PRINT → SESSION CLEAR → IDLE
발견     선택     준비      작성       확인      출력      비움
```

시민의 **의도가 점점 구체화되는 하나의 제품**이다.
⛔ 서로 다른 세 개의 웹페이지처럼 만들지 않는다.

| 상태 | 한 일 | ⛔ 하지 않는 일 |
|---|---|---|
| **IDLE** | 이 기계가 무엇인지 알린다 | 민원 선택 · 개인정보 입력 · 시정홍보 · 캐러셀 |
| **MAIN** | 작성할 서식을 고르게 한다 | 준비물 상세 · 서식 장문 설명 |
| **START** | 고른 것을 확인하고 준비시킨다 | 모든 유의사항 나열 |
| **WRITING** | 질문에 답하게 한다 | (동결된 Reference UI) |

# 2. 공통 골격 — 네 구역, 세 배치

모든 상태가 **같은 네 구역**을 쓴다. 상태가 바뀌면 구역이 생기거나 사라지는 것이 아니라
**자리와 내용이 바뀐다.**

| 구역 | 하는 일 |
|---|---|
| **BAR** | 상단 바 `--topbar-h`(74px). 로고·기관명·서식 이름·도구. **한 번도 사라지지 않는다** |
| **ASK** | 지금 시민에게 말을 거는 곳 |
| **PAPER** | 종이. **연속성의 축**(§6) |
| **RAIL** | 참조 정보. 안심 안내는 **바닥 고정**(§7) |

```
배치 0  IDLE            BAR + PAPER(중앙 대형) + ASK(문장)         RAIL 없음
배치 1  MAIN            BAR + [ASK 위 / PAPER 아래] + RAIL
배치 2  START·WRITING   BAR + ASK / PAPER / RAIL                  = --cols
```

⚠️ **배치 2 는 동결된 Writing 의 `--cols` 토큰을 그대로 쓴다.**
1920 기준 실측 **ASK 794 / PAPER 858 / RAIL 252**.

# 3. 상태별 레이아웃과 정보 위계

## 3-1. IDLE — 발견

```
┌─ BAR ─ 로고·기관명 ───────────────── (도구 감춤) ────────────┐
│                                                            │
│              군포시 민원 서식 작성 도우미                      │
│         ┌──────────────────────────────┐                   │
│         │  ○○○ 신 청 서                 │                   │
│         │  ──────────────────────────  │  ← PAPER 중앙 대형  │
│         │  성명    [        ]          │     8~10초 시연 반복 │
│         │  생년월일 [        ]          │                    │
│         │  연락처   [▓▓▓▓]  ← Focus    │                    │
│         │  주소    [        ]          │                    │
│         └──────────────────────────────┘                   │
│            질문에 답하면, 신청서가 완성됩니다                   │
│               아무 곳이나 눌러 시작하세요                       │
└────────────────────────────────────────────────────────────┘
```

**정보 위계** ① 이게 무엇을 하는 기계인가 ② 어떻게 되는가(종이가 채워지는 시연)
③ 지금 눌러도 된다 ④ 기관 표기(작게)

- CTA 는 장치 중립 표현을 쓴다(§19 Input-Agnostic) — 「**아무 곳이나 눌러 시작하세요**」
- BAR 의 도구(작성예시·초기화·미리보기·인쇄·크게 보기)는 **감춘다.** 로고·기관명만 남는다

## 3-2. MAIN — 선택

```
┌─ BAR ─ 로고·기관명 ─────── 오늘 날짜 ────── 🔍 크게 보기 ──────┐
├──────────────── 본문 ────────────────────┬──── RAIL ───────┤
│  무엇을 하러 오셨나요?                       │ 이렇게           │
│                                          │ 도와드립니다      │
│  ┌───────┬───────┬───────┬───────┐       │ 1 왜 묻는지      │
│  │🛂      │👶      │💍      │🕊      │       │ 2 쉬운 말로     │
│  │여권     │아이 출생│혼인     │사망     │  ASK  │ 3 적히는 자리   │
│  │만들기   │신고하기 │신고하기 │신고하기 │       │                 │
│  │여권발급 │출생신고서│혼인신고서│사망신고서│      │                 │
│  │신청서   │        │        │        │       │                 │
│  └───────┴───────┴───────┴───────┘       │                 │
│  ┌───────┬───────┬───────┬───────┐       │                 │
│  │✍️ 개명  │📄 이혼  │🧾 가족  │🏠 부동산│       │                 │
│  │신고하기 │·친권자  │관계증명 │거래     │       │                 │
│  │개명신고서│신고하기 │서 발급  │신고하기 │       │                 │
│  └───────┴───────┴───────┴───────┘       │                 │
│  🤔 어느 것인지 모르겠어요 — 직원에게 여쭤볼게요 │                 │
├──────────────────────────────────────────┤ ──────────────  │
│    ┌──────────────────────────────┐      │ 안심하고         │
│    │ ○○○ 신 청 서                  │ PAPER│ 작성하세요       │
│    │ ────────────────────────     │ 정지 │ ✓ 저장 안 함     │
└────┴──────────────────────────────┴──────┴─────────────────┘
```

**정보 위계** ① 질문 ② 카드 8개(**큰 글씨 = 시민이 하려는 일 / 작은 글씨 = 행정명칭**)
③ 여기 없으면 직원(§8 Human Handoff) ④ PAPER(조용) ⑤ RAIL

- 카드는 **4열 × 2행**. 기관별로 4장이면 **4열 1행**으로 줄고 **PAPER 띠가 그만큼 올라온다**
- PAPER 는 **윗부분만** 보인다 — 「책상 위에 놓인 종이」
- ⛔ PAPER 는 Main 에서 **움직이지 않는다.** 선택 UI 와 경쟁시키지 않는다
- ⛔ 「이용 가능 / 준비 중」 배지는 쓰지 않는다 — 전부 같은 값이면 정보가 아니라 소음이다(§14)
- 보조 분류(`category`)는 **화면에 드러내지 않는다.** 20종 이하에서는 1차 탐색을 강제하지 않는다

## 3-3. START — 준비

```
┌─ BAR ─ 로고·기관명 ─ 여권발급신청서 ─ 날짜 ─ 🔍 크게 보기 ─────┐
├──── ASK 794 ────────┬──── PAPER 858 ───┬──── RAIL 252 ─────┤
│ 여권을 만드시려는     │ ┌──────────────┐ │ ○ 여권발급신청서    │
│ 것이 맞나요?         │ │여권발급신청서  │ │                   │
│  여권발급신청서       │ │──────────────│ │ 준비하셨나요?       │
│                     │ │              │ │ ✓ 여권용 사진 1장  │
│ 이런 것을 여쭤봅니다   │ │  (빈 서식)    │ │ · 기존 여권(있으면) │
│  약 15가지 · 5분 정도 │ │              │ │                   │
│                     │ │              │ │ ───────────────   │
│ 준비물               │ │              │ │ 안심하고 작성하세요 │
│ ✓ 여권용 사진 1장    │ │              │ │ ✓ 저장 안 함       │
│ · 기존 여권(있으면)   │ │              │ │ ✓ 자리 비우면 지움 │
│  없어도 작성하실 수   │ └──────────────┘ │ ✓ 출력물 직접 수령 │
│  있습니다            │                  │                   │
│ [← 다시 고르기]      │                  │                   │
│ [작성 시작 →]        │                  │                   │
└─────────────────────┴──────────────────┴───────────────────┘
```

**정보 위계** ① **고른 것이 맞는가**(되돌아갈 길 포함) ② 얼마나 걸리나 ③ 준비물 ④ 시작

- ⛔ **막지 않는다.** 준비물이 없어도 [작성 시작]으로 갈 수 있다
- ⑥ 결정대로 **경로와 무관한 공통 준비물만** 말한다.
  성인·미성년·대리처럼 **경로가 정해진 뒤의 추가 준비물은 각 서식 안의 `ready` 가 맡는다**
  (여권의 `SCREENS.ready` 를 제거하지 않는다 — 역할이 다르다)
- 여기부터 **배치 2**다. Writing 과 같은 골격이다

# 4. Generic Paper 규격 (동결)

Idle 과 Main 이 **같은 하나의 Generic Paper** 를 쓴다.

| | |
|---|---|
| **정체** | ⛔ **특정 실제 민원서식을 모사하지 않는다.** 가상 신청서다 |
| **구성** | **제목 + 일반적인 필드 약 4개.** 그 이상 늘리지 않는다 |
| **필드 예** | 성명 · 생년월일 · 연락처 · 주소 (실제 서식의 칸 이름을 그대로 베끼지 않는다) |
| **값** | ⛔ **실제 개인정보가 입력된 것처럼 보이지 않게 한다.**<br>가상 인물 또는 추상 글자만 쓴다. 주민등록번호 형태·실제 전화번호 형태 금지 |
| **쓰이는 곳** | IDLE(중앙 대형·시연) · MAIN(하단 띠·정지). **둘이 같은 종이다** |
| **쓰이지 않는 곳** | START 부터는 **고른 서식의 실제 빈 서식**으로 바뀐다 |

⛔ **8종 실제 서식 배경을 허브에 싣지 않는다.** 저사양·범용 원칙(§19)과 파일 크기 때문이다.

# 5. Idle 시연 규격 (동결)

| | |
|---|---|
| **한 주기** | **8~10초** |
| **보여주는 것** | 필드 **3개 정도**만. `Focus → 작성 → 다음 필드` 순서로 **천천히** |
| **끝맺음** | 한 사이클 뒤 **잠시 정지**했다가 자연스럽게 초기화 |
| ⛔ **금지** | 빠른 pulse · 튀는 효과 · 반복 강조 · 동시 다중 애니메이션 |
| **감소 모션** | `prefers-reduced-motion` 에서는 **자동 작성 시연을 하지 않는다.**<br>완성 전/후의 뜻이 전달되는 **정적 상태**로 대체한다 |

⚠️ **CSS 규칙만으로는 부족하다.** 공통 토큰 블록의 `@media (prefers-reduced-motion: reduce)`
는 CSS transition/animation 만 끈다. **JS 로 도는 시연은 `matchMedia` 로 직접 분기해야 한다**
(여권의 `calmScroll()` 과 같은 방식).

# 6. Paper Lifecycle (동결) — 연속성의 축

| 상태 | 위치 | 내용 | 움직임 |
|---|---|---|---|
| **IDLE** | 중앙 대형 | Generic Paper | 시연 반복(§5) |
| **MAIN** | 하단 띠 · 윗부분만 | Generic Paper | **정지** |
| **START** | CENTER | **고른 서식의 빈 서식** | 정지 |
| **WRITING** | CENTER | 고른 서식 | Current Focus 이동 + 값 채워짐 |
| **REVIEW** | CENTER | 다 채워진 서식 | 정지 |
| **PRINT** | — | 종이가 화면을 떠난다 | |
| **CLEAR** | — | 아무것도 없다 | |

> **한 바퀴가 종이의 여정이다.**
> 떠 있다 → 책상에 놓인다 → 눈앞으로 온다 → 채워진다 → 다 찬다 → 프린터로 간다 →
> 치워진다 → 다시 떠오른다

**Main → Start 의 Paper 변화 하나가 전체 서비스의 연속성을 담당한다.**

# 7. RAIL 규칙 (동결)

```
[상단]  작성 진행          WRITING 부터
[중단]  준비하셨나요?       START 부터
[대체]  이렇게 도와드립니다   MAIN 에서만 — 위 둘이 없을 때 그 자리를 채운다
[하단]  안심하고 작성하세요   MAIN~REVIEW 항상 · 바닥 고정
```

1. **하단(안심 안내)은 어떤 상태에서도 같은 자리에 있다.** `margin-top:auto` 로 이미 그렇다.
2. **위쪽은 상태가 바뀔 때만 바뀐다.** 같은 상태 안에서 질문이 넘어갈 때는 **숫자만** 변한다.
   → §10 「질문이 바뀔 때마다 정보 전체가 바뀌지 않는다」를 이것으로 지킨다.
3. RAIL 은 **IDLE 에만 없다.** 나머지 상태에는 항상 있고 폭이 같다(`--rail-w`).

# 8. BAR 규칙 (동결)

| | 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|---|
| IDLE | 로고·기관명 | — | **감춤** |
| MAIN | 로고·기관명 | — | 날짜 · 크게 보기 |
| START | 로고·기관명 | **서식 이름** | 날짜 · 크게 보기 · 서식 목록 |
| WRITING | 로고·기관명 | 서식 이름 | + 초기화 · 미리보기 · 인쇄 |

1. **왼쪽은 네 상태에서 한 번도 움직이지 않는다.**
2. 오른쪽 도구는 **필요해질 때 늘어난다.** 줄어들지 않는다.
3. ⚠️ 도구 칸은 `auto`(제 너비)로 두고 **기관명이 먼저 줄어들게** 한다.
   버튼 폭을 깎아 맞추면 기관명이 긴 곳에서 두 줄로 접힌다(2026.08.24 에 겪었다).

# 9. 전환 규칙 (동결) — 무엇이 움직이고 무엇이 남는가

## IDLE → MAIN (깨어남)

| 움직인다 | PAPER 가 **중앙 대형 → 하단 띠로 내려가 정착.** 시연이 멈춘다<br>ASK 가 대표 문장 → **질문 + 카드 8장**<br>RAIL 이 나타난다 |
|---|---|
| **그대로** | **BAR 왼쪽**(로고·기관명) · **PAPER 자체**(사라졌다 다시 그려지지 않는다. 내려가 앉는다) |

## MAIN → START (구체화) — **핵심 전환**

| 움직인다 | **PAPER 가 하단 띠 → CENTER 로 올라와 자리 잡고,<br>Generic Paper → 고른 서식의 실제 빈 서식으로 구체화된다**<br>ASK 가 Start 내용으로 전환된다<br>RAIL 의 「이렇게 도와드립니다」 자리에 「준비하셨나요?」가 들어온다<br>BAR 가운데에 서식 이름이 나타난다 |
|---|---|
| **그대로** | BAR 왼쪽·오른쪽 · **RAIL 하단의 안심 안내** · RAIL 폭 |
| ⛔ **금지** | **선택한 카드가 날아가거나 확대되어 CENTER 로 이동하는 애니메이션.**<br>카드는 그 자리에서 ASK 전환에 흡수된다 |

> **이 Paper 변화 하나가 전체 서비스의 연속성을 담당한다.** 다른 장치를 덧대지 않는다.

## START → WRITING (실제 페이지 전환)

| 움직인다 | ASK 안의 내용만 「확인·준비」 → 「첫 질문」<br>PAPER 에 Current Focus 가 첫 칸을 짚는다<br>RAIL 에 「작성 진행」이 더해진다 |
|---|---|
| **그대로** | **BAR 전부 · 세 영역 폭 · PAPER 위치와 크기** |

| 전환 | 움직인다 | 그대로 |

| → REVIEW | ASK 가 질문 → 요약. [다음]이 [신청서 인쇄]로 | BAR · PAPER(다 채워진) · RAIL |

# 11. 구현 제약 (동결)

## Start 와 Writing 의 기하를 맞춘다

START 는 `index.html` 안에, WRITING 은 각 서식 HTML 안에 있다.
[작성 시작]에서 **페이지가 실제로 교체된다.** 전환이 안 보이려면 기하가 같아야 한다.

- `--cols` **같은 토큰**을 쓴다 (1920 기준 ASK 794 / PAPER 858 / RAIL 252)
- `--topbar-h` 74px · PAPER 안쪽 여백 · `width:min(210mm,100%)` 동일
- `--rail-w` 252 / `--rail-w-narrow` 214 동일

그 위에 **전환 덮개**를 씌워 흰 깜빡임만 가린다.

## 건드리지 않는 것

- ⛔ **인쇄물** — 절대좌표·`@media print`·서식 이미지·Print Marker
- ⛔ **동결된 여권 Reference UI** — `SCREENS.ready` 포함
- ⛔ **`FORM_KEYS`·환경설정 계약** — `key` 이름을 바꾸지 않는다
