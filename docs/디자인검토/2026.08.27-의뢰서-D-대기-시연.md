# 의뢰서 D — 대기 시연의 연출 (2026.08.27)

> **이 의뢰도 「만들어 오세요」가 아니라 「이보다 나으면 주시고, 아니면 그대로 두라고 말해 주세요」입니다.**
> 지금 도는 것을 §3 에 초 단위로 적었습니다.

---

## 0. 이 문서를 쓰는 법 (의뢰하는 쪽이 읽는 곳)

1. **§1~§8 을 통째로 복사해** AI에게 붙여 넣습니다. 갈무리는 **`shots/hub-00-시연`** 이 핵심이고
   `hub-01-첫화면`·`hub-03-카드펼침`을 함께 올리면 앞뒤가 보입니다.
2. ⛔ **다른 의뢰(A 모션 값 · B 시각 값 · C 아이콘)와 섞지 마십시오.**
   과제 A 는 **토큰 값**을 정하고, 이 문서는 **시연이라는 하나의 연출**을 봅니다.
3. 여러 곳에 같은 문서를 주고 §8 로 채점해 하나를 고릅니다.
4. 「그대로 두는 것이 낫다」도 정상적인 결과입니다.

> ⚠️ **정지 이미지로는 이 화면을 다 볼 수 없습니다.** §3 의 초 단위 표를 읽어 주십시오.
> 필요하면 30초 화면 녹화를 함께 드립니다.

# 여기서부터가 AI에게 주는 내용입니다

## 1. 무엇을 보고 계신가

군포시 민원실 **창구 옆 키오스크**의 첫 화면입니다. 시민이 민원을 고르면 정부 공식 신청서가
질문에 따라 채워지고, 종이로 인쇄해 창구에 냅니다. 접수도 전송도 하지 않습니다.

**아무도 안 건드릴 때 이 화면이 스스로 시연합니다.**

| | |
|---|---|
| **화면** | 1920×1080 가로 (일부 기관은 1080×1920 세로) |
| **거리** | **서서** 봅니다. 지나가다 곁눈으로 보는 사람도 있습니다 |
| **쓰는 사람** | 민원실 방문 시민. **고령자가 많습니다.** 대부분 처음 보고 다시 오지 않습니다 |
| **환경** | 오프라인 Electron(Chromium 130). 재사용 사무용 PC 에서도 돌아야 합니다 |

화면은 세 영역입니다 — 왼쪽 **ASK**(민원 목록) / 가운데 **PAPER**(종이) / 오른쪽 **RAIL**(안내).
그 위에 **BAR**(상단 바). 이 네 구역은 **시연 중에도 생기거나 사라지지 않습니다.**

## 2. 이 시연이 하려는 일 — 딱 하나입니다

> **「이것은 지금 당신이 사용할 수 있는 도구다」를 알리는 것.**

공용 PC 앞에서 시민이 **「이걸 내가 만져도 되나?」**라고 느끼지 않게 하는 것이 전부입니다.
그래서 **시정홍보도 아니고 광고판도 아닙니다.** 별도 대기 화면을 만들지 않고,
**첫 화면 그대로가 스스로 쓰이는 모습을 보여 줍니다.**

## 3. 지금 도는 것 — 초 단위로

한 서식당 **2.8초**, 8종이면 한 바퀴 **22.4초**. 끝나면 첫 서식으로 돌아가 계속 돕니다.

```
0.00s  ┌ 왼쪽 목록에서 카드 한 장이 강조된다 (테두리 + 옅은 배경 + 아이콘이 대표색으로)
       │ ⛔ 「골라짐」 표시가 아니다. 코드에서도 다른 이름을 쓴다
0.00s  │ 가운데 종이가 0.34초에 걸쳐 흐려진다 (갈아끼우기)
0.17s  │ 종이 내용이 그 서식의 것으로 바뀐다 — 서식 이름 + 그 서식이 묻는 항목 5개
0.29s  │ 1번 항목의 값이 채워진다 ┐
0.75s  │ 2번 항목                │  한 줄당 0.34초에 걸쳐
1.21s  │ 3번 항목                │  왼쪽에서 오른쪽으로 드러난다
1.67s  │ 4번 항목                │  (손으로 적어 나가는 결)
2.13s  │ 5번 항목                ┘
2.80s  └ 다음 카드로 — 위를 되풀이
```

**종이에 보이는 것** (예: 혼인신고서)

```
              혼인신고서
      ────────────────────────────
      남편 성명     김도현
      아내 성명     이서연
      등록기준지    군포시 산본로 000
      증인 2인      박준호 · 최수빈
      신고인        ▁▁▁▁▁▁▁▁      ← 아직 안 채워진 칸
                              ─────
        작성 예시입니다 · 질문에 답하시면 이렇게 채워집니다
```

**멈추고 다시 켜지는 규칙**

| | |
|---|---|
| **멈추는 조건** | `pointermove`·`pointerdown`·`keydown`·`wheel`·`touchstart` — **무엇으로든**. 마우스가 움직이기만 해도 |
| **멈추면** | 카드 강조가 사라지고 종이가 **비워진다**(「서식을 골라 주세요」). ⛔ 연출을 덧대지 않는다 |
| **다시 켜지는 때** | 아무 조작 없이 **3분**(기관 설정값) |
| **감소 모션** | `prefers-reduced-motion` 이면 **시연을 아예 돌리지 않는다.** 첫 화면 그대로 정지 |

**값 목록**

```
한 서식에 머무는 시간      2800ms
종이 갈아끼우기            170ms 뒤 내용 교체 · 흐림 340ms
첫 줄이 채워지기 시작       120ms
줄 사이 간격               460ms   ← (2800 - 500) / 5 로 계산한다
한 줄이 드러나는 시간       340ms
시연 시작 직후 무시 구간     400ms  ← 커서 아래 요소가 바뀌며 브라우저가 합성하는 mousemove 를 막는다
다시 시연으로               180000ms (3분, 기관 설정)
```

## 4. ⛔ 뒤집을 수 없는 것

여러 차례 뒤집어 본 끝에 내린 결정입니다. **이것을 되돌리는 안은 받을 수 없습니다.**

| | 왜 |
|---|---|
| **별도 대기 화면을 만들지 않는다** | 화면을 나누면 「깨어남」이라는 전환을 설계해야 하고, 그 순간 다른 제품처럼 보입니다. 화면이 하나면 이을 자리가 없습니다 |
| **캐러셀 · 시정홍보 · 배너** | 이 화면의 목적은 하나입니다(§2). 광고판이 되는 순간 실패합니다 |
| **시연이 짚는 카드에 「골라짐」 표시를 쓰지 않는다** | 시연이 끝난 뒤에도 시민이 고른 것처럼 남습니다 |
| **시연이 카드 펼침판을 여닫지 않는다** | 여닫을 때마다 아래 카드가 밀려내려가 목록이 출렁입니다. 대기 화면은 조용해야 합니다 |
| **실제 서식 그림은 「고른 것」에만** | 시연·hover 까지 실제 서식을 띄우면, 눌러도 화면이 그대로여서 **누름이 아무 일도 안 한 것처럼** 보입니다 |
| **값은 전부 가상 인물 · 「작성 예시」라고 적는다** | 앞사람 개인정보가 남아 있는 것처럼 보이면 이 제품의 가장 큰 강점이 무너집니다 |
| **빠른 pulse · 튀는 효과 · 동시 다중 애니메이션** | 재사용 사무용 PC 에서 돌아야 하고, 조용해야 합니다 |
| **네 구역(BAR/ASK/PAPER/RAIL)은 생기거나 사라지지 않는다** | 시연 중에도 상단 바를 감추지 않습니다 — 「이 화면을 쓰는 모습」이어야 앞뒤가 맞습니다 |

## 5. 무엇을 부탁드리는가

**아래 여섯 가지에만 답해 주십시오.** 각각 「그대로」도 정상적인 답입니다.

**D-1. 리듬** — 한 서식에 2.8초가 맞습니까? 8종 한 바퀴 22.4초는 어떻습니까?
지나가는 사람이 **한 서식만이라도 끝까지 보고 지나갈** 시간이 목표입니다.

**D-2. 순서** — 지금은 **카드 강조와 종이 갈아끼우기가 동시**입니다.
어느 쪽이 먼저여야 합니까? 아니면 지금이 맞습니까?

**D-3. 채우는 방식** — 지금은 **다섯 줄을 다 채우고** 다음으로 넘어갑니다.
- 다 채우는 것이 맞습니까, **두세 줄만 채우다** 넘어가는 편이 나읍니까?
- 왼→오른쪽으로 드러나는 방식이 맞습니까? (다른 방식이 있다면 **성능 제약** 안에서)
- 채워진 값이 다음 서식으로 넘어갈 때 **어떻게 사라져야** 합니까?

**D-4. 한 바퀴 뒤** — 지금은 **쉬지 않고 계속** 돕니다. 쉬어야 합니까? 쉰다면 몇 초, 그동안 화면은?

**D-5. 멈춤** — 지금은 어떤 입력으로든 **즉시** 멈추고 종이가 비워집니다.
이게 너무 갑작스럽습니까? ⛔ 다만 §4 대로 **연출을 덧댈 수는 없습니다** —
「그대로」이거나, **덧대지 않고도 되는 방법**이어야 합니다.

**D-6. 감소 모션** — 지금은 **아예 돌리지 않습니다.** 이 판단이 맞습니까?
아니라면 `prefers-reduced-motion` 에서 무엇을 보여 줘야 합니까?

## 6. 답변 형식 — **이 형식으로만** 주십시오

⛔ **영상·GIF·프로토타입·CSS 파일·코드를 주지 마십시오.** 붙일 자리가 없습니다.
필요한 것은 **값과 순서**입니다.

```markdown
## 요약
(3줄 이내. 무엇을 왜 바꿨는지 · 몇 개를 바꿨는지)

## 값
| 항목 | 지금 | 제안 | 왜 |
|---|---|---|---|
| 한 서식에 머무는 시간 | 2800ms | 3400ms | … |
| 줄 사이 간격 | 460ms | (그대로) | … |

## 순서          ← D-2 · D-3 일 때
0.00s  …
0.20s  …
(초 단위로 적어 주십시오)

## 답
| # | 질문 | 답 | 왜 |
|---|---|---|---|
| D-1 | 리듬 | 3.4초로 | … |
| D-4 | 한 바퀴 뒤 | **그대로**(쉬지 않음) | … |

## 넘기지 못한 것
(§4 제약 때문에 제안하지 못했지만 짚고 싶은 것. 없으면 「없음」)
```

- 「왜」는 **한 줄**이면 됩니다. 다만 **이 용도(서서 보는 민원실 키오스크·고령자·지나가는 사람)에
  근거해야** 합니다. 「요즘 이렇게 합니다」는 근거로 쓸 수 없습니다.

## 7. ⛔ 받지 않는 답

| | |
|---|---|
| 별도 대기 화면 · 캐러셀 · 시정홍보 | §4 |
| 「Idle 전용 브랜딩 화면을 만들자」 | 화면이 하나여야 하는 이유가 §4 에 있습니다 |
| 실제 서식을 시연에 띄우자 | 눌러도 화면이 그대로여서 누름이 안 읽힙니다 |
| 소리 · 음성 안내 | 민원실입니다. 소리를 내지 않습니다 |
| 사람 사진 · 일러스트 · 3D | 오프라인이고, 종이가 주인공입니다 |
| 「더 역동적으로」 같은 말 | 붙일 수 없습니다. **초와 순서를 주십시오** |

| # | 기준 | 떨어지면 |
|---|---|---|
