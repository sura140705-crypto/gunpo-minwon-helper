## 2. 가장 큰 변화 — Main 재설계 (2026.08.23 ~ 08.27)

발표에서 쓸 수 있는 **Before → Problem → Decision → After** 이야기가 가장 잘 남아 있는 대목입니다.

### Before — 2026.08.23 이전의 첫 화면

```
상단 바   로고 · "군포시 민원 서식 작성 도우미" · 기관명 · 오늘 날짜
빨간 띠   개인정보 안내 2줄
hero      "어떤 서식을 작성하시나요?" + 설명 2줄
카드       행정 분류 4구역으로 묶인 8장
           (여권 / 가족관계등록 신고 5장 / 증명서 발급 / 부동산)
하단      이용 안내 5줄
           본문 폭 max-width:1080px 가운데 정렬
```

📷 **자료** : `docs/디자인검토/2026.08.23-현황-메인화면과-화면초기화.md` §5 에 구조와 수치가
글로 남아 있습니다. 그림은 git 에서 꺼냅니다(§0).

### Problem — 무엇이 문제였나

당시 문서에 적어 둔 것 그대로입니다.

1. **여권 새 화면과 조형 언어가 달랐다.** 같은 키오스크에서 첫 화면과 다음 화면이
   **다른 프로그램처럼** 보였다
2. **1080px 폭.** 1920 화면에서 양옆이 420px 씩 비었다
3. **배지가 정보를 주지 못했다.** 8종이 전부 「이용 가능」이면 없는 것과 같다
4. **어르신이 8장 중에서 고르는 일 자체가 어려웠다.** 「가족관계등록 신고」와
   「증명서 발급」의 차이를 시민이 알아야 하는 구조였다 — 실제로는 **「등본 떼러 왔다」**고 온다
5. **아무도 안 쓰는 동안의 화면이 없었다.** 허브가 그냥 떠 있었다

그리고 설계상의 난제 하나 —
**여권의 세 영역은 「서식」이 있어서 성립하는데, 첫 화면에는 서식이 없었다.**

### Decision — 무엇을 정했나

| | → [UX_DECISIONS](../UX_DECISIONS.md) |
|---|---|
| 행정 분류를 걷어내고 **시민의 말 카드**를 평평하게 | ① |
| 첫 화면도 **세 영역**으로 — 가운데는 **고른 서식의 종이** | ②③ |
| 별도 Start 화면을 만들지 않고 **카드를 그 자리에서 펼친다** | ④ |
| 별도 대기 화면을 만들지 않고 **첫 화면이 스스로 시연한다** | ⑨ |
| 실제 서식은 **고른 것에만** — 선명도가 곧 확정의 단계 | ③ |

가운데가 빈다는 난제는 이렇게 풀렸습니다 — **종이가 이 화면의 주인공이 되었습니다.**
고르기 전부터 「무엇을 쓰게 되는지」가 보이고, 아무도 안 쓸 때는 그 종이가 시연을 합니다.

## 4. 앞으로 화면을 동결하는 방법

큰 변화가 들어갈 때마다 **그 시점의 화면을 이 폴더에 고정**합니다.

```bash
# 1) 지금 화면으로 갈무리를 다시 뽑는다
python tools/design-shots.py

# 2) 이 폴더에 날짜 이름으로 동결한다 (예: 정식 서비스 개시)
mkdir -p "docs/history/2026.09.__-정식서비스"
cp "docs/디자인검토/shots/hub-01-첫화면.png" \
   "docs/디자인검토/shots/hub-03-카드펼침.png" \
   "docs/디자인검토/shots/pass-03-입력화면.png" \
   "docs/history/2026.09.__-정식서비스/"

# 3) 같은 폴더에 caption.md 를 쓰고, 아래 §1 연표에 한 줄을 더한다
```

- **날짜는 점 표기**(`2026.09.01`)입니다. 하이픈으로 끊으면 이 PC 의 DRM/DLP 가
  개인정보로 오인해 문서를 암호화합니다.
- 폴더 이름은 `<날짜>-<무엇>` — 예: `2026.08.27-Main재설계`
- **전부 복사하지 마십시오.** 그 변화를 설명하는 **3~5장**이면 됩니다. 나머지는 git 에 있습니다.

### 각 동결본에 함께 남길 것 (`caption.md`)

```markdown
# 2026.09.01 — 정식 서비스 개시

| | |
|---|---|
| **날짜** | 2026.09.01 |
| **상태** | 정식 서비스 |
| **무엇이 바뀌었나** | (한두 줄) |
| **왜 바뀌었나** | (한두 줄 · UX_DECISIONS 번호로 연결) |
```

네 줄이면 충분합니다. **길게 쓰면 아무도 안 씁니다.**
