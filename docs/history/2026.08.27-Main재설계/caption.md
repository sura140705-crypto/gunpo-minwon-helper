## Before → Problem → Decision → After

발표에서 쓸 이야기의 뼈대입니다. 자세한 것은 [`../README.md`](../README.md) §2.

### Before (`01`)

```
빨간 띠   개인정보 안내 2줄
hero      "어떤 서식을 작성하시나요?"
카드       행정 분류 4구역으로 묶인 8장
           (여권 / 가족관계등록 신고 5장 / 증명서 발급 / 부동산)
           본문 폭 max-width:1080px 가운데 정렬
```

### Problem

1. **여권 새 화면과 조형 언어가 달랐다** — 첫 화면과 다음 화면이 다른 프로그램처럼 보였다
2. **1080px 폭** — 1920 화면에서 양옆이 420px 씩 비었다
3. **배지가 정보를 주지 못했다** — 8종이 전부 「이용 가능」이면 없는 것과 같다
4. **어르신이 8장 중에서 고르는 일 자체가 어려웠다** — 행정 분류를 알아야 했다.
   실제로는 **「등본 떼러 왔다」**고 온다
5. **아무도 안 쓰는 동안의 화면이 없었다**

그리고 설계상의 난제 —
**여권의 세 영역은 「서식」이 있어서 성립하는데, 첫 화면에는 서식이 없었다.**

### Decision

| | |
|---|---|
| 행정 분류를 걷어내고 **시민의 말 카드**를 평평하게 | ① |
| 첫 화면도 **세 영역**으로 — 가운데는 **종이** | ② |
| **선명도가 곧 확정의 단계** — 실제 서식은 고른 것에만 | ③ |
| 시연 중 종이가 **실제로 채워진다** — 「질문에 답하면 신청서가 완성됩니다」 | ③ |
| 아이콘을 **단색 선 아이콘 한 벌**로 — 이모지는 OS마다 다르고 여러 색을 쓴다 | ⑯ |
| 별도 Start 화면 대신 **카드를 그 자리에서 펼친다** | ④ |
| 별도 대기 화면 대신 **첫 화면이 스스로 시연한다** | ⑨ |

### After (`02`~`05`)

가운데가 빈다는 난제는 이렇게 풀렸습니다 — **종이가 이 화면의 주인공이 되었습니다.**
고르기 전부터 「무엇을 쓰게 되는지」가 보이고, 아무도 안 쓸 때는 그 종이가 시연을 합니다.

> ⚠️ **아직 남은 것** — 나머지 7종은 **자리만** 여권에 맞췄고 흐름은 다릅니다.
> 세로형은 전용 배치가 아니라 세 영역을 위아래로 쌓은 것입니다.
> 모션·시각 토큰의 **값**은 외부 검토 중입니다.
