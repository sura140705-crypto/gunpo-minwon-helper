## 2-3. 각 영역의 실제 구현

### BAR ✅
- `.topbar` — 높이 `--topbar-h` 74px · 배경 `--surface-head` `#fbfaf7`
- 왼쪽 : 로고(`height:38px`) + 기관명 + 부제
- 오른쪽 : 오늘 날짜(`13.5px`) + `[크게 보기]` (`.btn.ghost`, 아이콘 16px + 글자 14.5px)
- 📌 **왼쪽은 어떤 상태에서도 움직이지 않습니다**(구조동결 §8)

### ASK ✅
- `.task-col` — `overflow:auto` · padding `30px 34px 24px`
- 질문 `.ask-q` — **34px / 800 / line-height 1.28 / letter-spacing -.035em**
- 부제 `.ask-sub` — `--fs-help` 17px / `--ink-muted`
- 카드 목록 `.cards` — `display:grid; gap:7px`
- **카드 `.card`** — 실측 **567 × 67px**(일반) / **725 × 80px**(크게)
  - `min-height: --row-h` · padding `10px 14px` · `border 1.5px --border-strong` · `radius --r-lg` 12px
  - 아이콘 `.card-ic` **21×21 인라인 SVG**(`currentColor` = `--ink-muted`)
  - 큰 글씨 `.card-label` `--fs-card` 20px / 작은 글씨 `.card-formal` `--fs-card-sub - 1` 14px
- 직원 문의 `.card-sub` — 점선 테두리 · `margin-top:auto` 로 **바닥 고정**

### PAPER ✅ — 네 단
📌 **실제 서식 그림은 「고른 것」에만** 씁니다(UX_DECISIONS ③).

| 상태 | 요소 | 무엇 |
|---|---|---|
| 아무것도 안 고름 | `.gp-empty` | 점선 종이 윤곽 + 「서식을 골라 주세요」 |
| 시연 | `.gp-sil` | **실루엣** — 서식명 + 항목 5개 + **값이 한 줄씩 채워짐** |
| hover·포커스 | `.gp-sil` | 실루엣 정지(항목만, 값 비어 있음) |
| 고름 | `.img-hold > .gp-img` | **실제 서식 축소본** + 흰 베일 `opacity .42` |
| 그림 없음(대비책) | `.gpaper` | 항목만 적힌 대체 종이 |

  ⛔ `width` 와 `max-height` 를 같이 주면 A4 비율이 무너집니다
- `.paper-fit` 이 `container-type:size` — 실루엣·그림이 이 상자의 **높이**를 잽니다

# 3. Main interaction 현재 상태

**코드를 읽어 확인한 것만** 적었습니다.

## 구현됨 ✅

| 동작 | 실제 구현 |
|---|---|
| **hover / 키보드 포커스** | 카드 테두리 `--blue` + 배경 `--blue-light` + 아이콘이 대표색으로 (`--dur-quick` 120ms) |
| **hover 시 오른쪽 Preview 교체** | ✅ **됩니다.** 단 **실루엣**입니다(실제 서식 아님). ⚠️ **아무것도 안 골랐을 때만** 바뀝니다 — 펼쳐 놓은 카드가 있으면 그것이 이깁니다 |
| **click** | ⛔ **바로 넘어가지 않습니다.** 그 자리에서 카드가 펼쳐집니다(`grid-template-rows 0fr→1fr`, `--dur-base`) |
| **다시 click** | 접히고 종이 자리도 비워집니다. **한 번에 하나만** 열립니다 |
| **[작성 시작]** | 그때 비로소 `href` 로 페이지 이동 |
| **고른 상태의 종이** | 실제 서식 축소본 + 흰 베일 `--veil:.42` |
| **Idle 자동 순회** | ✅ **돕니다.** 2.8초마다 카드를 짚고 종이를 갈아 끼우며 값을 한 줄씩 채웁니다 |
| **Idle → 기본** | ✅ `pointermove`·`pointerdown`·`keydown`·`wheel`·`touchstart` **무엇으로든** 즉시 멈춤 |
| **다시 Idle 로** | ✅ 무동작 `idleMs`(기본 3분) |

## 9-2. 📌 Ready 의 정의

| | |
|---|---|
| **무엇인가** | **서식별 선택 상태**(Form-specific optional state)입니다 |
| ⛔ **아닌 것** | 공통 Start/Ready **화면**이 아닙니다. 📌 **만들지 않습니다** |
| **여권** | ✅ `SCREENS.ready` 를 **여권의 공식 Ready 로 유지**합니다 |

| **Catalog 의 `ready`** | 📌 공통 화면을 만들기 위한 데이터가 **아닙니다.** 서식별 준비정보를 관리하는 **metadata** 입니다. 지금은 카드 펼침판이 그것을 읽어 보여 줄 뿐입니다 |

⚠️ 그래서 「Ready 가 없다」는 것은 **결함이 아닙니다.** 그 서식에 필요하지 않다는 뜻입니다.

## 9-3. ✅ Human Handoff — 지금 코드에 **세 가지**가 있습니다

⚠️ 셋은 서로 **다른 동작**입니다. 이름만 비슷합니다.

# 12. Claude Code 최종 구현 Checklist

## 12-1. 받아야 하는 명세

| 영역 | 필요한 것 | 출처 | 상태 |
|---|---|---|---|
| **Layout** | ASK/PAPER/RAIL 비율(일반·크게) · BAR 높이 · 여백 | Stitch | ✅ 지금 값 있음(§4-1) |
| **Color** | 면·잉크·테두리 값 · 대표색 **파생 규칙** | Stitch(과제 B) | ⬜ 대기 |
| **Typography** | 14개 크기 두 벌 · weight · letter-spacing | Stitch(과제 B) | ⬜ 대기 |
| **Radius / Shadow / Spacing** | 토큰 값 | Stitch(과제 B) | ✅ 지금 값 있음(§4-6) |
| **아이콘** | `path` 문자열 10개 | 의뢰서 C | ⬜ 대기 |
| **Component — 카드** | 기본/hover/focus/눌림/펼침 **다섯 상태** | Stitch + Lovable | ⬜ 대기 |
| **Component — 입력** | 기본/포커스/오류/비활성 | Stitch | ⬜ 대기 |

| **Click** | 눌림 피드백 | Lovable | ✅ 결정됨(quick+out) |

