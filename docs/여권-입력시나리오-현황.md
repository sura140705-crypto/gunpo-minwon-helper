# 여권발급신청서 도우미 — 현재 입력 시나리오 (개편 논의용)

> **작성 2026.08.18** · 대상 파일 `passport-helper-v1.html`(손작성 1,751줄)
>
> **이 문서의 쓰임**: 업무 담당자들에게서 수정 의견이 많이 올라와, 여권 도우미의 **입력 흐름을
> 새로 설계**하려 한다. 이 문서는 그 논의의 출발점 — **지금 무엇을 어떤 순서로 묻고 있는지**를
> 빠짐없이 적은 현황판이다. 새 시나리오를 짜는 사람(사람이든 AI든)이 이것만 읽고도 현재를
> 파악할 수 있도록, 리포 내부 사정을 모른다는 전제로 썼다.
>
> 새 시나리오는 이 문서를 바탕으로 작성 → **담당자 확인** → 그다음 구현 순서로 간다.

---

## Ⅰ. 무엇을 만드는 것인가

경기도 군포시 민원실에 놓는 **키오스크용 신청서 작성 도우미**다. 여권을 포함해 8종이 있고,
그중 여권이 가장 복잡하다.

**핵심 성질** — 새 시나리오를 짤 때 이 전제가 흔들리면 안 된다.

| | |
|---|---|
| 무엇을 출력하나 | **실제 법정 별지서식 위에 값을 얹어 인쇄**한다. 화면은 실물 서식을 그대로 재현한 미리보기다 |
| 왜 정확해야 하나 | 인쇄물이 **창구 접수용 원본**이다. 여권 판독기가 읽으므로 칸 위치가 틀리면 접수가 안 된다 |
| 누가 쓰나 | 민원실을 찾은 시민. **고령자 비중이 높다.** 처음 보는 화면에서 혼자 끝까지 가야 한다 |
| 어떻게 도나 | **완전 오프라인**. 외부 통신 0. 입력값은 브라우저 메모리에만 있고 어디에도 저장·전송되지 않는다 |
| 초기화 | 3분 무동작 시 자동 초기화, 인쇄 직후에도 초기화(개인정보 보호) |
| 서명·사진 | 도우미는 **글자만** 채운다. 서명·날인·사진 부착은 인쇄 후 창구에서 손으로 한다 |

**화면 배치**: 넓은 화면에서 왼쪽이 안내창(코치), 오른쪽이 서식 미리보기. 시민이 코치에
답하면 오른쪽 서식의 해당 칸이 즉시 채워지고, 지금 다루는 칸은 하이라이트된다.

## Ⅱ. 현재 흐름 한눈에 — 10단계 고정

**모든 이용자가 10단계를 전부 지난다.** 건너뛰기는 없다. 앞으로만 검증을 받고, 뒤로는 자유롭게
돌아갈 수 있다.

```
1 체크사항 → 2 신청인 → 3 여권 → 4 기존여권 → 5 로마자 → 6 긴급 → 7 추가 → 8 수령 → 9 서명 → 10 완료
   (준비물)   (이름·      (종류·   (있음/     (영문     (비상    (대부분  (방문/   (본인/   (검토·
              주민번호)   기간·면수) 없음/모름) 이름)     연락처)  비워둠)  우편)    대리)    인쇄)
```

상단에 10칸짜리 진행 표시줄이 있고, 각 칸에 짧은 이름(`체크사항 · 신청인 · 여권 · 기존여권 ·
로마자 · 긴급 · 추가 · 수령 · 서명 · 완료`)이 붙는다.

## Ⅲ. 단계별 상세

각 단계는 **질문 한 줄 + 「왜 묻는지」 설명 + 입력칸 + 상황별 안내/경고**로 이뤄진다.
`*` 는 필수 항목이다.

### 1단계 · 사전 체크리스트 〔입력 없음〕

- **질문**: "창구 방문 전, 아래 항목을 미리 준비해 주세요"
- **왜**: "없는 항목이 있어도 괜찮아요. 작성 후 창구에서 도움받으세요."
- **보여주는 것**: 신분증 / 여권 사진 1매(6개월 이내·흰 배경·3.5×4.5cm) / 기존 여권 /
  수수료
- **항상 뜨는 안내**: 사진 규격(최근 6개월·흰 배경·보정 합성 불가)

### 2단계 · 신청인 정보

- **질문**: "신청인의 기본 정보를 적어 주세요"
- **왜**: "신분증과 한 글자도 다르지 않아야 접수됩니다. 입력값은 저장되지 않고 화면·인쇄물에만 쓰입니다."

| 항목 | 필수 | 형식·도움말 |
|---|---|---|
| 한글 성명 `nameKor` | ★ | 신분증대로 |
| 주민등록번호 `jumin` | ★ | 숫자 13자리, 입력하면 자동으로 `------` 정리 |
| 본인 연락처 `phone` | ★ | 자동 하이픈, "만료 안내 문자를 받는 번호" |

- **실시간 검증**: 주민번호가 13자리 미만이면 경고, 13자리인데 형식이 틀리면 "다시 확인" 경고.
  연락처 자리수 부족도 경고.
- **실시간 표시**: 주민번호를 다 넣으면 그 자리에서 **만 나이와 미성년 여부**가 뜬다.
  미성년이면 "유효기간 5년이 자동 적용되고, 인쇄 시 「법정대리인 동의서」가 함께 출력됩니다."
- **항상 뜨는 안내**: 본인 작성이 원칙 / 미성년은 법정대리인 가능(동의서 필요) / 그 밖의 대리는
  위임장·관계 증빙 필요.

> 💡 **왜 신청인 정보가 여권 선택보다 먼저인가** — 주민번호로 나이를 알아야 다음 단계에서
> 유효기간 선택지를 통제할 수 있기 때문이다. 이 순서에는 의도가 있다.

### 3단계 · 여권 선택

- **질문**: "여권 종류·기간·면수를 골라 주세요"
- **왜**: "자주 신청하는 값(일반·10년·58면)을 미리 골라 두었어요."

| 항목 | 선택지 (⭐=기본 선택) |
|---|---|
| 여권 종류 `kind` ★ | ⭐**일반** / 관용 / 외교관 / 긴급 / 여행증명서 |
| 여행증명서 구분 `travelType` | 왕복 / 편도 — **종류가 여행증명서일 때만** 나타남 |
| 유효기간 `period` ★ | ⭐**10년** / 단수(1년) / 잔여기간 / 5년 / 5년 미만 |
| 면수 `pages` ★ | ⭐**58면** / 26면 — **긴급·여행증명서면 아예 안 보임** |

**자동 보정 규칙**

- 미성년이 「10년」을 누르면 → **막고** "만 18세 미만은 10년을 선택할 수 없어 5년으로 안내됩니다"
- 종류를 「긴급」으로 바꾸면 → 유효기간이 **단수(1년)로 강제**되고 면수 선택이 사라짐(12면 고정)
- 긴급에서 다른 종류로 바꾸면 → 유효기간이 10년으로 되돌아감
- 여행증명서가 아니면 → 왕복/편도 선택이 지워짐

**경고**: 관용·외교관을 고르면 "공무 목적의 특수 여권으로 소속 기관의 추천·확인을 거쳐야
합니다. 일반 신청 대상이 아니니 창구 직원에게 확인하세요." — **다만 작성은 계속 진행된다.**

### 4단계 · 기존 여권

- **질문**: "기존에 쓰던(또는 만료된) 여권이 있으신가요?"
- **왜**: "기존 여권이 있으면 로마자 성명을 반드시 그 여권과 똑같이 적어야 해서, 먼저 여쭤봅니다."
- **선택지** `hasPassport` ★ : 있음 / 없음 / **모름**("잘 모르겠어요 — 직원이 확인")
- **항상 뜨는 안내**: 만 18세 미만·생애 최초·개명/서명 변경·특수여권은 온라인 신청이 제한되어
  방문 접수가 필요하다.

> ⚠️ **선택 결과가 다음 단계를 바꾸지 않는다.** "있음"이든 "없음"이든 5단계 로마자 성명은
> 똑같이 나온다. 묻기만 하고 분기하지 않는다.

### 5단계 · 로마자 성명

- **질문**: "여권에 들어갈 로마자(영문) 이름을 정해 주세요"
- **왜**: "여권을 처음 신청하거나 로마자성명을 바꿀 때만 적습니다. 한 번 정하면 바꾸기 매우 어렵습니다."
- **쉬운 말 풀이**(접힘): "로마자 표기 — 한글 이름을 영어 알파벳으로. 예: 홍길동 → HONG GILDONG"
- **자동 추천**: 2단계의 한글 이름을 보고 로마자 후보를 제시, 누르면 입력됨

| 항목 | 필수 | 비고 |
|---|---|---|
| 로마자 성 `romanSur` | ★ | 자동 대문자 변환 |
| 로마자 이름 `romanGiven` | ★ | 자동 대문자 변환 |

### 6단계 · 긴급 연락처

- **질문**: "긴급 연락처를 적어 주세요"
- **왜**: "해외에서 사고가 났을 때 연락할 사람입니다. 본인이 아닌 가족·지인의 연락처를 적습니다."
- **항목**: 성명 `emgName` ★ / 신청인과의 관계 `emgRel` ★ / 전화번호 `emgPhone` ★
- **경고**: 긴급연락처 번호가 2단계의 본인 번호와 같으면 "다른 분(가족·지인)의 번호를 적어 주세요."

### 7단계 · 추가 기재

- **질문**: "해당하는 것만 적어 주세요 (대부분 비워 둡니다)"
- **왜**: "해당 사항이 없으면 그대로 [다음]을 누르시면 됩니다."
- **필수 없음.** 전부 선택 항목이다.

| 항목 | 설명 |
|---|---|
| 등록기준지 `regBase` | "담당공무원이 요청할 때만" |
| 배우자 로마자 성 `spouseRoman` | "여권에 spouse of ○○를 넣고 싶을 때만" |
| 점자여권 `braille` | 희망 / ⭐희망 안 함 |

### 8단계 · 수령 방법

- **질문**: "완성된 여권을 어떻게 받으시겠어요?"
- **선택지** `mailService` : ⭐**방문 수령**(추가 요금 없음) / 우편(등기) 수령(요금 별도)
- 우편을 고르면 → **받으실 주소** `mailAddr` ★ 입력칸이 나타나고, "등기우편 요금은 별도"
  안내가 붙는다. 주소는 전용 입력 위젯이고 "입력하시면 서식에 이렇게 들어갑니다 → …" 로
  실시간 미리보기를 보여 준다.
- 방문 수령으로 되돌리면 입력했던 주소는 지워진다.

### 9단계 · 신청·서명 〔가장 복잡한 단계〕

- **질문**: "이 신청서를 작성·제출하는 분은 누구신가요?"
- **선택지** `applyBy` ★ : ⭐**본인** / 대리인

**여기서 앞서 알아낸 미성년 여부와 조합되어 세 갈래로 갈린다.** 그리고 갈래마다 **추가
입력칸이 최대 9개까지** 그 자리에서 펼쳐진다.

| 경우 | 판정 | 추가로 묻는 것 | 인쇄물 |
|---|---|---|---|
| **A. 성인 + 본인** | 기본 | 없음 | 신청서 1쪽 |
| **B. 미성년** (본인/대리 무관) | 주민번호로 자동 판정 | 법정대리인 성명★(본인 신청 시) · 관계★ · 주민번호 · 신청인 주소★ · 법정대리인 주소(다를 때만) | 신청서 + **법정대리인 동의서** 2쪽 |
| **C. 성인 + 대리인** | 선택 | 수임인 성명★ · 생년월일 · 주소★ · 전화★ · 위임인과의 관계★ · 〔위임인 성명·생년월일 = 자동, 수정 불가〕 · 위임인 주소 | 신청서 + **위임장** 2쪽 |

- B와 C는 **상호 배타적**이다. 미성년을 대리인이 신청해도 그 대리인이 곧 법정대리인이므로
  동의서 경로(B)로 처리하고 위임장은 만들지 않는다.
- C에서 위임인(본인) 성명·생년월일은 2단계 입력에서 **자동으로 채워지고 수정할 수 없다.**
  주소는 8단계에서 우편 주소를 적었다면 그것이 자동으로 들어오고 수정할 수 있다.
- 긴 안내문이 붙는다(동의서/위임장 각각 3~5줄).

### 10단계 · 확인·완료

- 입력한 모든 값을 **서식 순서대로** 나열한다. 안 채운 항목은 「미입력」으로 표시.
- **「창구 직원에게 여쭤볼 항목 (N건)」** 목록 — 비어 있는 항목을 모아 보여 주고,
  「잘 모르겠어요」로 넘어온 단계의 항목에는 🤔 를 붙인다. 다 채웠으면 "✓ 모든 항목이
  입력되었습니다."
- **예상 수수료·처리기간** — 종류·기간·면수·나이로 계산(예: 10년 58면 52,000원, 만 8세 미만
  5년 58면 35,000원, 긴급 50,000원). 관용·외교관·여행증명서·잔여기간·5년 미만은 계산하지
  않고 "창구에서 안내받으세요". 처리 약 7~10일.
- 서명·사진 안내, 조건부 동의서/위임장 안내, **인쇄 설정 주의**(여백 «없음» · 배율 «100%»).
- **[🖨️ 신청서 인쇄]** 버튼.

## Ⅳ. 화면을 움직이는 규칙

| 규칙 | 동작 |
|---|---|
| **[다음]** | 필수 항목이 비어 있으면 **막고** 첫 빈 칸으로 커서를 옮긴다. 형식 오류도 막는다 |
| **「🤔 잘 모르겠어요」** | 모든 단계 아래에 있는 버튼. 누르면 **검증을 건너뛰고** 다음 단계로 가고, 그 단계 항목이 10단계의 「직원에게 여쭤볼 항목」에 모인다 |
| **[이전]** | 언제든 자유롭게 되돌아간다 |
| **진행 표시줄 클릭** | **이미 지나온 단계로만** 이동 가능(앞으로 건너뛰기 불가 — 검증 우회 방지) |
| **Enter 키** | 다음 입력칸으로, 마지막 칸이면 다음 단계로 |
| **[미리보기]** | 완성된 서식을 크게 보는 모달 |
| **[초기화]** | 입력 전체 삭제 |
| **[작성예시(성인)/(미성년자)]** | 테스트용. 가상 인물 값으로 전부 채운다. 키오스크에서는 담당자 점검용 |

## Ⅴ. 데이터와 인쇄물

입력값은 `state.data` 하나에 모이고, **좌표맵**이 그 값을 서식 이미지 위 절대좌표에 얹는다.
칸 종류는 세 가지다.

- **체크박스** — 종류·왕복편도·면수·기간·점자·우편 (해당 좌표에 ✔)
- **격자칸** — 한글성명(8칸)·주민번호(13칸)·전화(13칸)·긴급연락처·로마자 성/이름(각 16칸)·
  배우자 로마자 성 — **글자 하나가 칸 하나**에 들어간다
- **자유 텍스트** — 등록기준지, 우편 상세주소 (줄바꿈 처리)

인쇄물은 **1쪽(신청서)**, 조건에 따라 **2쪽(동의서 또는 위임장)** 이 자동으로 덧붙는다.

## Ⅵ. 지금 알려진 문제 (개편이 필요한 이유)

담당자 의견을 받기 전에, 코드를 읽어 파악한 구조적 문제들이다. 새 시나리오는 최소한 이것들을
해소해야 한다.

1. **누구나 10단계를 전부 지난다.** 성인이 본인 여권을 새로 만드는 가장 흔한 경우도 「기존
   여권」·「추가 기재」·「신청 방식」을 다 거친다. 실제로 값을 넣는 칸은 몇 개 안 되는데
   화면은 열 번 넘긴다.

2. **분기 판정이 뒤에 몰려 있고 흩어져 있다.** 미성년 여부·대리 여부·특수여권 여부를 판정하는
   조건식이 여러 군데 흩어져 있고, 결과가 **9단계에 가서야** 화면에 나타난다. 미성년자
   동의서가 필요하다는 사실을 시민은 9단계에서 처음 제대로 만난다.

3. **이미 고른 값을 뒤에서 덮어쓴다.** 3단계에서 10년을 고른 뒤 주민번호가 미성년으로 판정되면
   유효기간이 5년으로 **자동 변경**된다. 시민 입장에서는 내가 고른 게 바뀌어 있다.

4. **특수 경우를 끝까지 데려간다.** 관용·외교관은 애초에 일반 창구 신청 대상이 아닌데,
   경고만 띄우고 10단계까지 다 작성하게 한다.

5. **4단계가 분기하지 않는다.** 기존 여권 유무를 묻지만 결과가 흐름을 바꾸지 않는다. 물어놓고
   쓰지 않으니 시민에게는 그냥 한 화면 더다.

6. **9단계가 과부하다.** 한 화면에서 선택 하나로 입력칸 9개가 펼쳐지고, 안내문이 다섯 줄
   붙는다. 가장 어려운 경우(대리·미성년)가 가장 복잡한 화면에 몰려 있다.

7. **용어가 어렵다.** 「수임인」·「위임인」·「법정대리인」·「등록기준지」·「잔여기간」이
   그대로 노출된다. 쉬운 말 풀이는 5단계 로마자에만 있다.

## Ⅶ. 새 시나리오를 짤 때의 제약 (반드시 지킬 것)

> 이 절은 **양보할 수 없는 선**이다. 화면 흐름은 크게 바꿔도 되지만 아래는 유지해야 한다.

**① 데이터 모델(`state.data`)의 모양을 바꾸지 마라.**
질문 흐름과 데이터는 분리돼 있다. 인쇄층은 `state.data` + 좌표맵만 읽는다. **필드 이름과
값의 형태가 그대로면 화면을 아무리 뒤집어도 인쇄물은 안 변한다.** 이 프로젝트에는
인쇄물 회귀를 픽셀 단위로 잡는 검증 도구가 있고, 데이터 모양을 지키면 그 안전망이 계속
작동한다. 필드를 새로 추가하는 것은 괜찮지만, **기존 필드를 없애거나 값의 표기를 바꾸면
서식 칸이 비거나 깨진다.**

**② 좌표는 못 바꾼다.** 법정 별지서식이 정한 칸 위치다. "이 항목을 서식의 다른 자리에 넣자"는
불가능하다. 다만 **묻는 순서·묶는 방식·표현**은 자유다.

**③ 서식에 없는 값을 새로 묻지 마라.** 인쇄할 칸이 없는 정보는 받아도 갈 곳이 없다.
(안내·분기 목적으로만 쓰고 인쇄하지 않는 질문은 가능하다 — 지금 4단계 「기존 여권」이
그런 경우다.)

**④ 개인정보는 화면에만.** 저장·전송 금지. 3분 유휴 초기화와 인쇄 후 초기화는 유지.

**⑤ 오프라인.** 외부 API·폰트·이미지 호출 불가. 파일 하나로 완결돼야 한다.

**⑥ 고령자 기준.** 글자 크기, 한 화면의 정보량, 되돌아가기 쉬움을 우선한다.

**⑦ 필수를 늘리지 마라.** 지금 설계는 "비워 두고 창구에서 물어봐도 된다"가 기본값이다.
「잘 모르겠어요」와 「직원에게 여쭤볼 항목」이 그 장치다. 이 안전판을 없애면 시민이 막힌다.

## Ⅷ. 터치스크린 · 아이콘 초기화면

향후 **터치스크린 모니터** 설치를 전제로, 첫 화면을 **아이콘 방식**으로 바꾸는 것을 검토
중이다. 함께 정할 점들:

- **어디까지가 아이콘인가** — 서식 8종을 고르는 첫 화면(허브)만인지, 여권 안에서도 「본인/대리」
  「성인/미성년」 같은 갈래를 큰 아이콘 버튼으로 고르게 할 것인지.
- **키보드 입력은 남는다.** 이름·주민번호·주소는 결국 글자를 쳐야 한다. 터치 전용이면
  **화면 키보드**가 필요하고, 한글 입력·자동 하이픈과 어떻게 맞물릴지 정해야 한다.
- **터치 목표 크기** — 지금 버튼은 마우스 기준이다. 손가락 기준으로 키우면 한 화면에 들어가는
  선택지 수가 줄어든다. 단계 설계에 직접 영향을 준다.
- **관리자 단축키 노출** — 현재 담당자용 기능이 `Ctrl+Shift+…` 단축키다. 키보드가 노출되는
  자리라면 시민이 누를 수 있다. 터치 도입과 함께 정리해야 한다.

## Ⅸ. 담당자에게 확인할 것

새 시나리오를 확정하기 전에 답이 필요한 항목이다. **이 목록을 그대로 들고 담당자와 앉으면
된다.**

**흐름**
1. 실제 창구에서 가장 흔한 경우는 무엇인가? (성인 본인 재발급 / 미성년 부모 동반 / 대리 …)
   → 그 경로를 가장 짧게 만든다.
2. 관용·외교관은 **작성 중단하고 창구 안내**로 돌릴까, 지금처럼 끝까지 쓰게 둘까?
3. 긴급여권·여행증명서는? (좌표가 이미 잡혀 있고 수요도 있어 계속 쓰게 하는 쪽을 권한다)
4. 「기존 여권」 질문은 실제로 무엇을 갈라야 하는가? 있음이면 로마자를 **잠그고** 기존 여권과
   같게 쓰라고 안내할까?

**입력 항목**
5. 실제로 접수 때 자주 비어 있거나 틀리는 칸은 무엇인가?
6. 반대로, 도우미가 묻지 않아 창구에서 매번 손으로 적게 되는 것이 있는가?
7. 「등록기준지」·「배우자 로마자 성」은 실제로 얼마나 쓰이는가? 감춰도 되는가?
8. 미성년·대리 서류(동의서·위임장)에서 창구가 실제로 확인하는 칸은 어디인가?

**충돌 처리**
9. 앞에서 「성인」이라고 답했는데 주민번호가 미성년으로 나오면 — **조용히 고칠까, 알려서
   고치게 할까?** (알려주는 쪽을 권한다. 2020.10 주민번호 체크섬 폐지로 오탈자를 잡을 수단이
   없어졌는데, 앞단의 답이 그 역할을 대신할 수 있다)

**표현**
10. 「수임인/위임인」 같은 법률 용어를 쉬운 말로 바꿔도 접수에 문제가 없는가?
    (인쇄물의 서식 문구는 그대로고, 화면 안내만 바꾸는 것)
11. 수수료·처리기간을 화면에 계속 표시할까? (금액이 바뀌면 유지보수 부담이 된다)

**터치**
12. 터치 모니터 도입 시기와 화면 크기·해상도는? 물리 키보드를 함께 둘 것인가?
