관련 : 「군포시 민원 서식 작성 도우미」 보안성 검토 결과 통보

## 1. 총괄

보안성 검토에서 지적해 주신 5개 항목에 대한 조치 결과입니다.
**프로그램 수정(기술적 조치)** 과 **운영 환경·인적 통제(보완 통제)** 를 함께 적용하였습니다.

| | 지적 항목 | 조치 결과 | 조치 방식 |
|---|---|---|---|
| ① | 인쇄 기능 보완 | **조치 완료** | 기술 — 지정 프린터 고정 · 대화상자/Ctrl+P 차단 · 대기열 3단 관리 |
| ② | 키오스크 보안 설정 강화 | **조치 완료** | 기술 — sandbox·devTools·이동·권한 차단 / **환경 — 전용 계정 + 셸 교체로 화면 이탈 차단** |
| ③ | 프로그램 종료 및 실행 통제 | **조치 완료** | 기술 — 중복 실행 차단 · 관리자 PIN 종료 |
| ④ | 개인정보 초기화 및 잔존 방지 | **조치 완료** | 기술 — 임시 경로·시작/종료 삭제 / **환경 — 디스크 복원 솔루션 + 일일 재부팅** |
| ⑤ | 프로그램 버전 관리 | **위험 수용 + 상향 계획** | 환경 — 오프라인·고정 콘텐츠로 노출 경로 없음(제7항) / 상향 일정 수립 |

- 조치 사항은 **프로그램(실행본) 자체를 수정**한 것이며, 서식 내용·좌표·화면 구성은 변경하지 않았습니다. 조치 후 인쇄물 19쪽 전체가 기존과 **픽셀 단위로 동일**함을 확인하였습니다.
- 지적사항이 구조적으로 해소되지 않는 **크롬(브라우저) 실행 방식은 폐지**하고, 전용 프로그램 한 가지로 일원화하였습니다(제8항).
- 본 키오스크는 **인터넷에 연결하지 않는 전용 PC** 로 운영하며, 문서 편집기 등 다른 프로그램을 설치하지 않습니다. 운영 환경 전반은 **제10항**에, 이행 기록 서식은 **〔붙임 4〕 운영 점검표**에 정리하였습니다.

## 2. 〔①〕 인쇄 기능 보완

### 가. 지적사항

- 인쇄 대화상자가 표시되고 한컴 PDF 등 가상 프린터를 선택할 수 있음
- 지정된 실물 프린터의 deviceName 설정, 인쇄 대화상자 및 Ctrl+P 차단 필요
- 프린터 대기열 일시중지 시 개인정보가 포함된 인쇄 작업이 대기열에 잔존

### 나. 확인 결과

지적을 확인하는 과정에서 **설계상의 결함**을 확인하였습니다.

현재 배포본은 인쇄 시 대화상자를 열지 않도록 만들어져 있으나, 그 처리는 화면에 **보호 장치를 덧씌우는**
방식이었습니다. 따라서 **덧씌우기가 실패하면 원래의 인쇄 대화상자가 그대로 남는** 구조였고,
그 경우 목록에서 `Hancom PDF` 등을 선택할 수 있었습니다.
**실패했을 때 안전한 쪽이 아니라 열린 쪽으로 동작**하는 것이 문제의 본질이며, 지적을 전적으로 수용합니다.

### 다. 조치 내용

| 조치 | 내용 |
|---|---|
| **출력 장치 고정** | 관리자가 지정한 실물 프린터(deviceName)로만 출력합니다. 기본 프린터를 따라가지 않으므로, 기본 프린터가 바뀌어도 다른 장치로 나가지 않습니다. |
| **지정 대상 검증** | 지정된 프린터가 파일로 저장하는 가상 프린터(포트 `PORTPROMPT:`·`nul:`·`SHRFAX:` 또는 알려진 PDF 저장 프린터 이름)로 판별되면 **인쇄를 거부**합니다. |
| **대화상자 차단** | 인쇄 대화상자를 열지 않습니다. 보호 장치가 정상 적용되었는지 **결과를 되읽어 확인**하고, 적용되지 않았으면 **인쇄를 하지 않고 안내 화면으로 정지**합니다(안전 우선 동작). |
| **Ctrl+P 차단** | 인쇄 대화상자 단축키를 입력 단계에서 차단합니다. |
| **인쇄 전 상태 점검** | 프린터가 일시중지·오프라인·용지 없음·덮개 열림 등 정상이 아니면 **인쇄 작업을 보내지 않고** 사유를 화면에 표시합니다. → 대기열에 쌓이는 것을 원천 차단 |
| **잔여 작업 회수** | 인쇄 후 60초가 지나도 대기열에 남아 있는 작업은 **자동으로 삭제**합니다. 프로그램 시작 시·종료 시에도 잔여 작업을 정리합니다. |
| **인쇄된 문서 유지 해제** | 프린터 속성의 `[인쇄된 문서 유지]` 가 켜져 있으면 정상 인쇄 후에도 작업이 남으므로, 설치 스크립트가 이 값을 끕니다. |
| **오류 안내** | 인쇄되지 않은 경우 **사유를 화면에 표시**한 뒤 첫 화면으로 돌아갑니다(종전에는 안내 없이 초기화되어 시민이 인지하지 못했습니다). |

인쇄가 거부되는 경우와 표시 문구는 다음과 같습니다.

| 상황 | 화면 표시 |
|---|---|
| 프린터가 지정되지 않음 | 프린터가 지정되지 않았습니다 (관리자 설정 필요) |
| 지정 프린터를 찾을 수 없음 | 지정된 프린터를 찾을 수 없습니다 : (이름) |
| 지정 프린터가 가상 프린터 | 파일로 저장하는 프린터는 사용할 수 없습니다 |
| 프린터 비정상 상태 | 프린터가 준비되지 않았습니다 : (사유) |
| 인쇄 보호 기능 미적용 | 지금은 이용할 수 없습니다 (작성 자체를 받지 않음) |

### 라. 확인 방법

- 프로그램을 `--selfcheck` 로 실행하면 **지정 프린터·포트·상태·[인쇄된 문서 유지]·대기 작업 수**가 결과 파일에 기록됩니다(제6항).
- 프린터를 일시중지한 상태에서 인쇄를 시도하면 **작업이 대기열에 생성되지 않고** 사유가 표시됩니다.

## 3. 〔②〕 키오스크 보안 설정 강화

### 가. 지적사항

- sandbox 및 devTools 설정이 명시적으로 확인되지 않음. 기본 설정·단축키 차단에만 의존하지 말 것
- 승인된 내부 화면 외 이동, 새 창, 외부 링크, 불필요한 권한 요청 차단
- Alt+Tab 및 Windows 키를 통한 화면 이탈 가능

### 나. 조치 내용

| 항목 | 조치 |
|---|---|
| **sandbox** | 렌더러 샌드박스를 **명시적으로 설정**하였습니다(종전에는 기본값에 의존). |
| **devTools** | 개발자도구 기능 자체를 **생성하지 않도록 설정**하였습니다. 단축키 차단(F12·Ctrl+Shift+I/J/C)은 이중 안전장치로 함께 적용합니다. |
| **Node 접근 차단** | 화면(렌더러)에서 시스템 기능에 접근할 수 없도록 차단하고, 프로그램과 화면 사이에는 **인쇄 요청 한 가지만** 노출합니다. |
| **화면 이동 제한** | 프로그램에 포함된 승인 화면(서식 8종·첫 화면·안내 화면) **외의 주소로는 이동하지 않습니다.** 시도 시 차단됩니다. |
| **새 창·외부 링크** | 새 창 생성을 전면 거부합니다. 프로그램 화면에는 외부 링크가 포함되어 있지 않습니다. |
| **권한 요청** | 카메라·마이크·위치·알림·장치 접근 등 **모든 권한 요청을 거부**합니다. |

### 다. 실제 적용 상태 확인

“기본 설정에만 의존하지 말고 실제 적용 상태를 확인하라”는 지적에 따라, **적용 여부를 프로그램이 스스로
점검해 파일로 출력하는 기능(`--selfcheck`)** 을 신설하였습니다(제6항). 개발 환경에서 실행한 결과는 다음과 같습니다.

```
[렌더러 보안]
  sandbox                      : [양호] true
  contextIsolation             : [양호] true
  nodeIntegration              : [양호] false
  devTools 열림 시도               : [양호] 차단됨
  인쇄 보호 장치                     : [양호] 적용됨
```

devTools 항목은 **실제로 개발자도구를 열도록 명령한 뒤 열리지 않았음을 확인**한 결과입니다.

### 라. Alt+Tab · Windows 키 — 셸 교체로 차단

**이 두 가지는 프로그램이 차단할 수 없습니다.** 윈도우가 프로그램보다 먼저 처리하는 입력이기 때문입니다.
따라서 **OS 차원에서 차단**하고, 프로그램은 만일의 이탈 시 **잔존을 막는 역할**을 맡도록 이원화하였습니다.

| 계층 | 조치 | 효과 |
|---|---|---|
| OS | 키오스크 **전용 계정 + 자동 로그온** | 관리자 환경과 분리 |
| OS | **셸(Shell) 교체** — 해당 계정의 셸을 탐색기 대신 본 프로그램으로 지정 | 바탕화면·작업표시줄·시작 메뉴가 **존재하지 않아** Alt+Tab 대상도, Windows 키로 열 것도 없음 |
| OS | 정책 — Windows 키 조합 사용 안 함, 작업 관리자 사용 안 함 | 잔여 우회 경로 차단 |
| 프로그램 | 창이 가려지면 **즉시 첫 화면으로 되돌려 입력 내용 삭제** | 만일의 이탈 시에도 개인정보 노출 없음 |
| 인적 | 민원실 **상시 도우미**가 이용 상황을 상시 확인 | 이상 이용 즉시 인지·조치 |

- 본 키오스크는 **본 프로그램 전용 PC** 이므로, 셸을 교체해도 잃는 기능이 없습니다.
- Windows 11 **Pro** 에서 적용 가능한 방식입니다(‘할당된 액세스’ 기능은 본 프로그램 형태에 적용되지 않습니다).
- 셸 교체 시에는 **점검·복구용 관리자 계정 로그인 경로를 반드시 확보**하고, 종료 PIN(제4항)을 **먼저** 설정합니다.
- 절차는 〔붙임 3〕 **제Ⅺ항 가목**에 수록하였습니다. 적용은 **정보통신과 협조**로 진행합니다.

## 4. 〔③〕 프로그램 종료 및 실행 통제

### 가. 지적사항

- 실행파일의 중복 실행이 가능함
- Ctrl+Shift+Q 및 Alt+F4 로 일반 사용자가 종료할 수 있음. 운영자 전용 종료 절차 필요

### 나. 조치 내용

| 항목 | 조치 |
|---|---|
| **중복 실행 차단** | 두 번째 실행은 즉시 종료되고, 이미 실행 중인 창이 앞으로 나옵니다. |
| **운영자 전용 종료** | `Ctrl+Shift+Q` 를 누르면 **관리자 PIN 입력 창**이 뜨고, PIN 이 일치해야 종료됩니다. |
| **Alt+F4 차단** | 창 닫기 요청을 가로채 **동일하게 PIN 확인을 거치도록** 하였습니다. Alt+F4 입력 자체도 차단합니다. |
| **단축키 범위 축소** | 종전 종료 단축키는 **OS 전역(global)** 으로 등록되어 다른 프로그램 사용 중에도 반응했습니다. 이를 **프로그램 창 내부로 한정**하였습니다. |

PIN 은 프로그램에 저장되지 않으며, 대조용 **해시(SHA-256)** 만 설정 파일에 기록됩니다.
설정은 설치 시 `관리자_개인정보보호_설정.bat /pin` 으로 수행합니다(〔붙임 3〕 제Ⅴ항).

### 다. 설계상 남겨 둔 사항 (사전 보고)

**PIN 을 설정하지 않은 상태에서는 종료를 막지 않습니다.** PIN 이 없는데 종료까지 차단하면,
전체화면으로 잠긴 키오스크를 해제할 수단이 사라져 **복구가 불가능**해지기 때문입니다.
이에 따라 **PIN 설정을 설치 필수 절차로 지정**하고, 점검 기능(`--selfcheck`)이
미설정 시 `[확인] 미설정 → PIN 없이 종료 가능` 으로 표시하도록 하였습니다.

## 5. 〔④〕 개인정보 초기화 및 잔존 방지

### 가. 지적사항

- 프린터 오류·강제종료 등 예외 상황에서 개인정보가 화면·임시파일·캐시·오류 로그·크래시 덤프 등에
  남지 않는지 추가 확인 및 보완

### 나. 조치 내용

| 경로 | 종전 | 조치 후 |
|---|---|---|
| **캐시·저장소** | 프로그램 **시작 시 1회** 삭제 | 시작 시 + **종료 시** 삭제. 저장 위치를 **윈도우 임시 폴더로 이동** |
| **크래시 덤프** | 기본 경로(사용자 프로필)에 잔존 가능 | 임시 폴더로 이동 후 **시작·종료 시 삭제**. 덤프에는 화면 메모리(입력값)가 포함될 수 있어 별도 조치 |
| **로그 파일** | — | **로그 생성을 비활성화**하였습니다. 오류 기록에는 프린터 상태 문구만 남으며 입력값은 포함되지 않습니다. |
| **강제 종료 시** | 다음 실행 전까지 잔존 | 저장 위치가 임시 폴더이고 **시작 시 삭제**하므로, 강제 종료되어도 **다음 실행이 정리**합니다. |
| **인쇄 대기열** | 대응 없음 | 제2항의 3단 조치(사전 차단·자동 회수·유지 해제) |
| **화면 잔존** | 인쇄 후·3분 무동작 시 초기화 | + **창이 가려지면 즉시 초기화** |

### 다. 환경 차원의 보강 — 디스크 복원 솔루션

키오스크 PC에는 **재부팅 시 디스크를 기준 상태로 복원하는 솔루션(PC보안관 등)** 을 적용하고,
**개점 전·폐점 후 재부팅을 일일 점검 항목으로 고정**합니다(〔붙임 4〕).

이로써 지적하신 “예외 상황에서의 잔존”은 **세 겹**으로 관리됩니다.

| 겹 | 무엇이 지우는가 | 언제 |
|---|---|---|
| 프로그램 | 캐시·저장소·크래시덤프 | 시작할 때 · 종료할 때 |
| 인쇄 경로 | 대기열 잔여 작업 | 인쇄 60초 후 · 시작·종료 시 |
| **디스크 복원** | **디스크 전체를 기준 상태로** | **재부팅할 때** |

> **다만 복원 솔루션이 프로그램 조치를 대체하지는 않습니다.** 복원은 재부팅 시점에만 일어나므로,
> 운영 중(주간)의 잔존은 프로그램이 처리해야 합니다. 두 가지는 **보완 관계**로 함께 운용합니다.

또한 이 PC에는 **문서 편집기(한글·오피스 등)를 설치하지 않으므로**, 종전 지적의 주요 위험이었던
`Hancom PDF` 가상 프린터가 **애초에 존재하지 않습니다.**
(윈도우 기본 가상 프린터인 `Microsoft Print to PDF`·`XPS`·팩스는 오피스와 무관하게 존재하므로,
설치 스크립트의 제거·윈도우 기능 끄기는 그대로 수행합니다.)

### 라. 추가 시험 방법 (제안)

지적하신 “충분히 시험하지 못한 예외 상황”에 대해 아래 절차로 시험하고 결과를 제출하겠습니다.

1. **프린터 오류** — 프린터 전원 차단 / 용지 제거 / 대기열 일시중지 각각의 상태에서 인쇄 시도
   → 인쇄 작업 생성 여부, 화면 초기화 여부, 스풀 폴더(`C:\Windows\System32\spool\PRINTERS`) 잔존 여부 확인
2. **강제 종료** — 입력 도중 전원 차단 / 작업 관리자 강제 종료
   → 재실행 후 입력값 복원 여부, 임시 폴더·크래시 덤프 잔존 여부 확인
3. **디스크 쓰기 추적** — Process Monitor 로 프로그램의 파일 쓰기 전량 기록
   → 개인정보가 포함된 쓰기 유무 확인
4. **화면 잔존** — 인쇄 직후·무동작 3분·창 전환 각각에서 이전 입력 노출 여부 확인

시험 일정과 입회 여부는 협의 요청드립니다.

## 6. 점검 기능 신설 (`--selfcheck`)

“설정이 명시적으로 확인되지 않았다”는 지적에 대응하여, **적용 상태를 프로그램이 직접 점검해
파일로 남기는 기능**을 신설하였습니다.

```
실행    : 군포민원서식도우미.exe --selfcheck
결과    : C:\ProgramData\군포민원서식도우미\점검결과_(날짜).txt
```

- 화면을 점유하지 않고 상태만 확인하므로 **운영 중에도 실행할 수 있습니다.**
- 기록 항목 — 프로그램·Chromium 버전 / 렌더러 보안(sandbox·개발자도구·인쇄 보호) / 설정(지정 프린터·PIN) /
  설치 프린터 목록과 가상 프린터 유무 / 지정 프린터 상태·포트·[인쇄된 문서 유지]·대기 작업 수 /
  저장소·크래시덤프 경로 / 차단 항목 목록
- **개인정보는 기록되지 않습니다.**
- 각 항목은 `[양호]` / `[확인]` 으로 표시되어, 미조치 항목이 그대로 드러납니다.

**키오스크 PC에서 실행한 결과 파일을 본 조치결과서의 증빙으로 제출**하겠습니다.
아울러 설치 시 1회, 이후 **주 1회** 실행을 운영 절차(〔붙임 3〕 제Ⅵ·Ⅶ항)에 반영하였습니다.

## 7. 〔⑤〕 프로그램 버전 관리 — 계획

### 가. 지적사항

- Electron 33.4.11 은 공식 지원이 종료된 버전이므로 지원 중인 안정 버전으로 상향
- 이후 Electron·Chromium 취약점 및 지원 종료 여부를 정기적으로 확인

### 나. 현황

지적하신 대로 **Electron 33 은 지원이 종료**되었습니다. Electron 은 8주 주기로 새 버전을 배포하며
**최신 3개 버전만 지원**합니다. 2026.08 기준 지원 버전은 **42 · 43 · 44**, 최신 안정판은 **44**(Chromium 152)입니다.

### 다. 운영 환경상 취약점 노출 경로 검토

표시 엔진(Chromium)의 보안 취약점은 대부분 **외부에서 들어온, 공격자가 제어하는 콘텐츠를 렌더링할 때**
성립합니다. 본 키오스크의 운영 조건은 다음과 같습니다.

| 조건 | 내용 |
|---|---|
| 네트워크 | **인터넷에 연결하지 않음.** 프로그램은 외부와 통신하지 않음 |
| 표시 콘텐츠 | **프로그램 안에 포장되어 함께 배포되는 고정 파일 8종**뿐. 외부 콘텐츠를 불러오지 않음 |
| 화면 이동 | 승인된 내부 화면 밖으로 이동 불가(제3항) |
| 외부 매체 | USB 저장장치 차단, 부팅 매체 차단(제11항) |
| 디스크 | 재부팅 시 기준 상태로 복원 |

즉 **취약한 코드가 남아 있더라도 그것을 실행시킬 입력 경로가 존재하지 않습니다.**
이에 따라 지원 종료 버전 사용은 **즉시적 보안 위험이 아니라 생애주기 관리 사항**으로 판단하고,
아래 라목의 일정에 따라 해소하되 그때까지는 **문서화된 위험 수용**으로 처리하고자 합니다(제12항 결재).

### 라. 조치 계획 및 선행 과제

**목표 버전은 Electron 44** 이며, 아래 선행 과제를 마친 뒤 상향합니다.

> **선행 과제 — 인쇄물 회귀 검증 도구 보강**
> 본 프로그램은 **서식 위에 절대좌표로 값을 얹어 인쇄**하므로, Chromium 이 바뀌면 **인쇄물의 칸 위치가
> 미세하게 달라질 수 있습니다.** 여권발급신청서는 기계 판독 대상이라 이 차이가 접수 오류로 이어집니다.
> 현재 보유한 인쇄 회귀 검증 도구는 데스크톱 크롬 기준이어서 **프로그램 자체의 인쇄 결과는 검증하지 못합니다.**
> 따라서 **프로그램 내부 인쇄 경로로 검증하는 도구를 먼저 만든 뒤**, 상향 전후 인쇄물을 대조하겠습니다.

| 단계 | 내용 | 예정 |
|---|---|---|
| 1 | 프로그램 내부 인쇄 경로 기반 회귀 검증 도구 제작 | 2026.08. |
| 2 | Electron 44 상향 후 인쇄물 19쪽 대조 | 2026.09. |
| 3 | 시험 인쇄(실물) 확인 후 재배포 | 2026.09. |

검증 없이 먼저 상향할 경우 **인쇄물 오류를 인지하지 못한 채 운영될 위험**이 있어 위와 같이 순서를 두었습니다.
조기 상향이 필요하다고 판단하시면 알려 주시기 바랍니다.

### 마. 표시 엔진 대안 검토 결과

“Electron 을 계속 쓰는 것이 타당한가”에 대해 아래 방식을 함께 검토하였습니다.

| 방식 | 인쇄 통제 | **오프라인에서의 버전 부담** | 인쇄물 재검증 | 비고 |
|---|---|---|---|---|
| **Electron (현행)** | 필요 기능 모두 확보 | 있음(반기 1회) | 상향 시 필요 | 현행 유지 |
| WebView2 (시스템 Edge) | 프린터 지정·여백·배율 지정 가능 | **동일하게 있음** | 필요 | 별도 개발 언어(.NET) 도입 필요 |
| Tauri (시스템 WebView) | **무음 인쇄 통제가 약해 직접 구현 필요** | 동일 | 필요 | 별도 개발 언어(Rust) 도입 필요 |
| 인쇄물 직접 생성(비-브라우저) | 완전 결정적 | **없어짐** | 전면 재작업 | 대규모 개편 |
| 브라우저(크롬·엣지) 키오스크 | **불가** — 대화상자·프린터 고정 불가 | — | — | 제8항 사유로 폐지 |

검토 결과는 다음과 같습니다.

1. **WebView2 의 장점은 이 환경에서 성립하지 않습니다.** 그 방식의 이점은 표시 엔진이 윈도우 업데이트로
   자동 최신화되는 것인데, **인터넷에 연결하지 않는 PC 에서는 자동 갱신이 오지 않습니다.**
   결국 고정 버전을 받아 수동으로 갱신해야 하므로 **현행과 부담이 같으면서**, 유지보수 언어만 하나 늘어납니다.
2. **표시 엔진을 쓰는 한 “엔진을 최신으로 유지하라”는 요구는 어느 방식에서도 따라옵니다.**
   이를 근본적으로 없애려면 인쇄물을 브라우저 없이 직접 생성하는 방식으로 전환해야 하는데,
   **서식 8종의 좌표 체계를 전면 재작업**하고 인쇄 정확도를 다시 검증해야 하므로 현 시점에는 적절하지 않습니다.
3. **어느 방식을 택하든 지배적인 비용은 “인쇄물이 그대로인지 확인하는 일”** 입니다.
   따라서 프레임워크 교체보다 **인쇄 회귀 검증 도구 확보가 선행되어야** 하며, 도구가 갖춰지면
   버전 상향도, 장래의 방식 전환도 검증 가능한 작업이 됩니다.

이에 따라 **현행 Electron 을 유지**하되, 라목의 일정으로 지원 버전으로 상향하고,
인쇄물 직접 생성 방식은 **장기 검토 과제로 기록**합니다.

### 바. 정기 점검 절차 (신설)

- **6개월마다** Electron 지원 버전·취약점 공지를 확인하고, 지원 종료 시 지원 버전으로 상향합니다.
- 상향 시에는 **반드시 인쇄물 대조와 실물 시험 인쇄**를 거칩니다.
- 위 내용을 〔붙임 3〕 제Ⅹ항 「보안 업데이트 주기」와 〔붙임 4〕 반기 점검에 명문화하였습니다.

| **일일**(개점 전) | 재부팅 / 첫 화면 / 프린터 상태 / **대기열 잔여 작업 0건** / 시험 인쇄·파기 | 점검자 서명 |
| **주간** | `--selfcheck` 전 항목 `[양호]` / 지정 프린터·PIN 유지 / 결과 파일 보관 | 점검자·책임자 서명 |
| **반기** | 표시 엔진 지원 여부 / 상향 시 인쇄물 대조 / 기준 이미지 재저장 | 점검자·책임자 서명 |

- 관리 책임자·점검 담당자·대리자를 지정하고, 도우미 배치 시 **교육 사항 8개 항목을 전달·기록**합니다.
- 사고 발생 시 조치·보고 경로를 유형별로 규정하였습니다(개인정보 노출 의심 시 **즉시 보고**).
- 점검 기록은 **1년간 보관**하며, 점검표에는 **시민의 개인정보를 기재하지 않습니다.**

### 라. 설치 시 유의사항 (자체 확인된 위험)

디스크 복원 솔루션과 본 프로그램을 함께 쓸 때 **설정이 복원되어 인쇄가 되지 않는 상황**이 발생할 수 있습니다.
프로그램이 프린터 지정을 읽지 못하면 **안전을 위해 인쇄하지 않도록** 만들어져 있기 때문입니다(제2항 다목).

이에 **설정 완료 → 점검 → 기준 이미지 저장** 순서를 〔붙임 3〕 제Ⅱ항에 명시하고,
**재부팅 후 `--selfcheck` 재확인**을 설치 절차의 마지막 단계로 두었습니다.
